# RP322 — внеигровой ответ без зависимости от SSE

## Исправление

RP321 live выявил неверные missing/игровые варианты после OOC, хотя после reload
в обеих отправках был виден read-only префикс. Отсутствие OOC в панели доставки
не было доказательством потери запроса: эта панель фильтрует purpose=user-turn.

Прежний `storyReplyPurpose` требовал XHR closed+finish+native link. Новый fallback
использует завершённую серверную пару из уже существующего ограниченного GET
истории. Совпадают мир, binding, чат, native parent, полный подтверждённый
исходящий текст, user/assistant IDs и завершённость обоих сообщений. Любой
существующий wire link должен быть согласован. Нужна одна локальная принятая
отправка, неоднозначность/изменение текста/чужая или неполная пара не угадываются.
Это read-only доказательство для UI, не восстановление игровой/платной authority.

Managed sync переиспользует своё чтение; для legacy при существующем принятом
OOC выполняется отдельный bounded GET. Ответ fetch не клонируется и не читается
расширением, поток/ответ сайта не заменяются. Snapshot кешируется только для
текущего мира/чата/URL/native anchor и версии отображённого ответа. Проза здесь
лишь инвалидирует cache, никогда не доказывает принадлежность. Генерация,
новая принятая отправка, смена scope/ответа и блокировка сбрасывают proof.
Обычные parent/edit/undo остаются прежними; чтение презентации не запускает
storyGameStatus/runStoryGame и не включает слежение. Поздние/stale GET отвергаются.

После GET плашка пересчитывается; скрытие вариантов работает и при выключенных
карточках. Следующий игровой ответ не наследует OOC. Поддержано исключение
игровых последствий локального OOC без XHR wire link по точному подтверждённому
user body/parent: оно не восстанавливает role roster/изображения/игровую authority.
Неподтверждённые источники и старые restored XHR не получают этот fallback.

## Проверки

TDD: два положительных теста (fetch/XHR без SSE proof) сначала падали на RP321,
затем прошли. Негативные проверки: scope, другой чат/выбранный ответ, текст,
parent, незавершённый user/reply, missing user, restored/unconfirmed/failed,
неоднозначность и конфликт существующего wire link. Входы не меняются.

Тесты клиента: один GET/cached reuse, переиспользование managed read, отсутствие
записей/включения tracking; смена мира/чата/URL/anchor/версии ответа, генерация,
блокировка/reset, поздний result, чужой origin, неправильная/неполная история.
Installed MV3: actual POST, virtual-list DOM, неправильный JSON, reload, 200 px,
RU/EN, ручной/managed/legacy и cards-off, fetch/XHR/XHR без SSE-маркеров;
следующий обычный игровой ход возвращает варианты. Итоги — текущий handoff.

Финальный полный unit: 325 файлов, 9 013 passed, 5 прежних todo, 0 failed;
`.output/rp322-unit-final.json`. TypeScript clean. Первый installed прогон
22/22 до дополнительных cards-off/cache-invalidation проверок; финальный
расширенный прогон 28/28. В первом расширении 6 cards-off ошибочно ожидали
character instruction при отключённых карточках; исправлено ожидание стенда,
не добавлялась лишняя инструкция. Присланный вопреки OOC choices JSON скрыт,
проверены также partnerIds/partnerId. Снимки 200 px RU/EN просмотрены:
`docs/benchmarks/rp322-ooc-{ru,en}-narrow-20261018.png`.
Упаковка отмечается отдельно в ROADMAP.

## Живой повтор после обновления Brave — пройден

После подтверждения установки пользователем проверен тот же RP319 мир/чат.
Прежняя последняя OOC уже получила нейтральный статус без recovery.
Три новые пары:

1. RU «Вне игры:» — гипотетическое возвращение Норы: правильное различение
   разрешения и состоявшейся передачи, состав 1 → 1, нет вариантов.
2. Игровое фактическое возвращение Норы: 1 → 2, «Обновлено после ответа»,
   четыре готовых хода. Никакой из них не выбран, предметы не передавались.
3. EN-маркер `OOC:` с русским вопросом — гипотетический уход: 2 → 2,
   правильный ответ об отсутствии одного условия, нейтральный статус, нет
   recovery/готовых ходов. После reload всё это сохранилось.

Readback восстановленных новых user rows 15/19 содержит read-only, без choice
mode; игровой row 17 — обычный character/choice mode, без read-only. Это
DOM readback, не сетевой перехват. Не определён реальный transport, не выполнено
full DB/events сравнение. Нейтральный мир не содержал новых структурированных
фактов: вопросы о тубусе используют и нативную переписку, не доказывают auto
extraction/бесконечное окно. Предыдущий RP321 failed остаётся историческим failed.

Сразу после OOC до завершения серверной сверки кратко появилась recovery-кнопка;
после GET исчезла. Settled UI/reload пройдены; устранение краткого мигания —
отдельная необязательная UX-задача, не повод угадывать по словам модели.
В этой live-итерации runtime не менялся, новая установка Brave не нужна.
Исходный чат оставлен открытым, черновик пуст, новых вкладок/окон нет. Нора
теперь в сцене вместе с Мирой. Личные миры не открывались.

Снимки: `docs/benchmarks/rp322-live-{before,ooc,game,ooc-after-game,reloaded}-20261018.png`.
