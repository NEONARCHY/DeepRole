# Персонажи и портреты

## Ручная правка и автоматические обновления

В редакторе видны поясняющие плашки: состояние сцены, текущие отношения, значения характеристик и отметки сыгранных событий могут обновляться после ответов DeepSeek, если получены подходящие изменения. Ручная правка применяется после «Сохранить персонажа» и заменяет соответствующие текущие значения общей игры лора. Используйте её для исправления ошибки или задания нужного состояния. Последующие ответы могут снова менять незакреплённые значения; фиксация запрещает автоматические изменения чисел, сохраняя ручное редактирование.

Плашки учитывают выключенное отслеживание и фиксацию. **Анкета** объясняется отдельно: обычные ответы не перезаписывают её постоянные поля, при включённом сопровождении пригодные сведения из сцен дополняют игровую анкету поверх исходного текста. Защищённые поля ждут проверки. [Режимы сопровождения](AUTOMATIC-MEMORY.md). Начальные значения, названия шкал, правила и условия событий задаёт пользователь. Просмотр плашки не меняет данные, не запускает DeepSeek и не требует подтверждения.

### Manual edits and automatic updates

Visible notices explain which current scene fields, relationships, characteristic values and event marks may update after DeepSeek replies. Saving a manual edit replaces the corresponding values in the lore’s shared game; later replies may update unlocked values again. Numeric locks and disabled tracking are reflected in the notice. Ordinary replies preserve original profile text, starting values and definitions. Enabled accompaniment can append source-backed game details; protected fields await review. [Accompaniment modes](AUTOMATIC-MEMORY.md). Viewing a notice does not change data or send a request.

## Возврат в предыдущий чат

После подключения того же лора к другому чату в предыдущем появится небольшое напоминание со ссылкой. При первом сообщении там DeepSeek получает скрытую просьбу один раз предупредить, что игра перенесена, и предложить актуальный чат. Это ответ вне сцены; после следующего сообщения можно продолжить игру здесь.

Отправку расширение не блокирует. **«Продолжить здесь»** скрывает плашку, отключает просьбу и делает этот чат актуальным, используя последние общие значения игры. Если новый чат удалён, можно остаться в старом. Ссылка не проверяет доступность чата на сервере. При неудачной отправке просьба остаётся для повтора; после принятой отправки не добавляется снова, включая перезагрузку. Подсказка расширения работает независимо от ответа модели.

Один лор использует одну общую игру: отношения, показатели, объединения, псевдонимы и настройки памяти сохраняются при смене чата. Старый чат показывает актуальные значения, но не записывает последствия, пока не выбран для продолжения. После одноразового предупреждения обычное следующее сообщение возобновляет игру здесь. [Подробное руководство](WORLD-GAME.md).

## Объединение и унаследованные имена

В **«История → Персонажи»** откройте **«Имена и псевдонимы»**, чтобы отключить или вернуть имя, подтверждённое в прохождении либо перенесённое в новую исходную точку. Исходные имена анкеты мира меняются в самой анкете. Общие имена нескольких людей не используются для автоматического подбора.

**«Объединить дубликаты персонажа»** предназначено для двух анкет одного человека. Выберите обе, сравните и укажите источники: анкета с правилами и изображениями, текущее состояние, отношения других персонажей. Ничего не складывается. При разных правилах выбирайте анкету и состояние из одной карточки. Проверьте имя, псевдонимы и отметку главного героя, затем подтвердите.

Объединение действует в общей игре этого лора, включая её продолжения в других чатах. Исходные карточки скрыты из актуального состава. Оригиналы и другая библиотека изображений сохраняются; новая карточка получает библиотеку выбранного источника. Кнопка отмены возвращает оригиналы. Если после объединения сыграны сцены, отмена возвращает историю к месту объединения и приостанавливает запись; сообщения чата остаются. Изменённая или используемая другими данными карточка не удаляется автоматически: отмена остановится.

Новая исходная точка закрепляет ранние решения. Перенесённое объединение видно в списке, но отмена через границу исходной точки не предлагается. Имена по-прежнему можно отключать отдельно. Генерация DeepSeek для этих действий не требуется.

### Merge scope

**Story → Characters → Merge duplicate characters** affects this lore’s shared game, including its continuation chats. Source cards are hidden from the current roster. Explicitly choose the profile/images, played state and incoming relationships; numbers are not combined. Originals remain intact. Undo restores originals and, when necessary, pauses recording at the merge scene. Edited or externally referenced merged cards block destructive undo. A new checkpoint fixes earlier merges; their aliases remain individually manageable. These tools do not call the model.

## Где найти нужное действие

Откройте **«История → Персонажи»** в основном меню. **«Персонажи из лора мира»** готовит первоначальный состав созданного или импортированного мира. **«Люди, найденные в игре»** ищет пропущенных персонажей в записанных сценах этого чата. Откройте **«Проверить персонажа»** для цитат, полей и привязки к существующей анкете. **«Дополнить сохранённую анкету»** собирает новые сведения для уже известного персонажа. Открытие раздела само не отправляет запрос модели.

Сначала подключите мир в **«Игре»**. Для поиска в сыгранных сценах включите запись истории; переписка до исходной точки не анализируется. Состояние записи видно сразу в **«Истории»**. Настройки **«Поведение персонажей»** относятся к аватаркам и правилам, а не к библиотеке анкет.

Правки проверки состава остаются при её закрытии и повторном открытии. Черновики каталога сохраняются при переключении страниц и разделов открытой панели. Для сохранения после перезагрузки подтвердите анкету; локальный несохранённый черновик не является резервной копией.

### Finding the right action

Open **Story → Characters**. **Characters from world lore** prepares the initial world cast; **People found during play** searches recorded scenes in this chat. Open **Review this person** for sources, fields and linking a saved profile. **Add details to a saved profile** handles new details for an existing person. Opening this view does not send a model request. Connect a world in **Play** and enable scene recording for played-history tools. Earlier messages before the starting point are not analysed.

Closing/reopening the same cast review and paging/navigating the open panel preserve local edits. Save a reviewed profile to retain it after reload; unsaved UI drafts are not backups. **Character behaviour** settings govern avatars and rules, not the profile library.

## Имена и псевдонимы в выбранной истории

В «История → Персонажи → Люди, найденные в игре» у найденного имени нажмите **«Это известный персонаж»**. Найдите сохранённую карточку по имени или псевдониму, проверьте описание, выберите её и нажмите **«Связать имя»**. Список имеет страницы; это не предел библиотеки. Связь не запускает генерацию и не копирует анкету, отношения, числа или изображения.

Имя начинает учитываться в этой истории с момента подтверждения. Общий мир и другие чаты не меняются. Другой вариант ответа исключает связь; возврат восстанавливает её. **«Убрать связь»** оставляет найденный кандидат для новой проверки. Связь переживает перезагрузку и резервную копию; новая исходная точка той же истории наследует её отдельно от мирового канона. «Убрать связь» относится к событию текущего каталога; отдельный список управления унаследованными именами пока не добавлен.

Если карточка переименована или псевдоним оказался общим, заимствование отключается с пояснением. Уберите связь и проверьте её заново. При другом человеке с уже известным именем модель может предложить отдельного кандидата: уточните имя, например «Алекс, курьер», перед подготовкой. Для такого кандидата используется только его отличающая исходная цитата, а не все записи про любого Алекса; недостающие факты могут не найтись.

Это ручное подтверждение личности, не доказательство модели и не объединение двух существующих карточек. В большой исходной подготовке мира разрешение псевдонимов пока не подключено. Поиск до исходной точки и смысловое разрешение местоимений/маскировок остаются отдельными этапами.

### Names in the selected story

For a found name in **Story → Characters → People found during play**, open **This is a known character**, search the saved profiles, check the description and explicitly **Link this name**. Nothing is generated or copied; world profiles, numeric state, relationships and images stay unchanged. The alias is used only in this selected story from approval onward. Other variants exclude it, returning restores it, and **Remove this link** keeps the original candidate.

Reload, encrypted backups and a new checkpoint of the same story preserve approved links separately from world canon. Renaming the saved profile or a later shared-name collision disables borrowed matching and explains why. A distinct namesake needs a qualified name before profile preparation; only their distinguishing source quote is used, so another person's facts are not retrieved through a shared name. Review missing details yourself. This does not merge existing cards or resolve aliases in the large original cast preparation.

## Большой исходный лор

Для мира больше 220000 символов **«Создать персонажей из лора»** сначала ищет имена в небольших частях источников, затем готовит по одной анкете с нужными выдержками. Каждая часть использует новый видимый служебный чат, открывающийся после очистки предыдущего. Историю делить на отдельные миры не требуется. Модель может пропустить людей или сведения — итог всё равно нужно проверить.

Прогресс чтения, найденные имена и готовые предложения сохраняются в этой локальной базе. После отмены, отказа или сбоя нажмите **«Продолжить подготовку»**: завершённые части не повторяются. Неудачную очистку сначала исправьте кнопками в статусе; отсутствие окна не доказывает удаления чата. Перезагрузка и разблокировка сами не отправляют новые запросы. Если лор изменён, **«Начать разбор изменённого лора заново»** отделяет новый разбор от старого.

Анкеты используют ограниченные выдержки по точному имени; местоимения и неизвестные псевдонимы могут не найтись. По старым отдельным записям не угадывается, кто физически находится в текущей сцене. Числа и отношения — предложения для проверки; сохранённые авторские поля и сыгранные значения защищены прежними правилами. Рабочее задание подготовки не включается в переносной backup, а сохранённые персонажи и лор включаются. После импорта копии процесс подготовки сам не возобновится.

### Large source lore

Above 220,000 characters, **Create characters from lore** reads bounded excerpts to find names, then prepares one profile at a time using literal-name excerpts. Each step opens a fresh visible service chat after verified cleanup. The story does not need splitting into worlds. Saved progress resumes explicitly after a failure or reload; completed steps are skipped. If sources changed, restart their analysis instead of mixing old and new proposals.

Review missing or ambiguous information; the catalogue does not prove a complete cast. Pronouns/unknown aliases may be missed, scene membership is not guessed from old excerpts, and scores remain proposals. Source text, author profiles and played values stay protected. Working cast jobs stay local and are excluded from portable backups; backups preserve saved lore and characters without restarting service requests.

## Очередь анкет из записанной истории

В «История → Персонажи → Люди, найденные в игре» покажите найденные имена. Отметьте **«В очередь анкет»** у нужных людей или **«Выбрать без готовой анкеты»** на текущей странице. Имя и авторские поля можно поправить перед запуском. **«Подготовить выбранные анкеты»** сохраняет эти черновики и готовит предложения по одному в видимых служебных окнах DeepSeek.

Готовые предложения остаются для проверки: выберите поля, поправьте текст и отдельно добавьте каждого персонажа в эту историю. Очередь не меняет общий мир, сыгранные числа, отношения, изображения или текущую сцену и не придумывает отсутствующие факты. Каждое имя требует отдельного запроса; выдержки с точным именем могут не охватить все сведения.

**«Остановить очередь»** сохраняет завершённые предложения. После закрытия панели, сбоя или перезагрузки покажите найденное и нажмите **«Продолжить сохранённую очередь»**: готовые анкеты повторно не запрашиваются. Игровой черновик/новый ответ останавливает подготовку, не перезаписывается. При смене истории очистите очередь и выберите имена заново; **«Очистить очередь»** не удаляет полученные предложения. Если временный чат не удалось убрать, сначала проверьте диагностику палочек. После reload ничего не отправляется модели само.

### Queue profiles from the recorded story

In **Story → Characters → People found during play**, show the found names, select **Queue profile** or **Select profiles not prepared** on the current page, edit names/drafts if needed, then click **Prepare selected profiles**. Draft snapshots and each verified proposal are saved; separate visible service windows run sequentially. Review fields and add each character explicitly. Shared world profiles, scene state, scores and images stay intact; missing facts are not invented.

Stop at any time, then **Continue saved queue** after reopening or reloading. Completed profiles are skipped. A game draft or changed story stops work. Clear a stale queue and select names again; clearing preserves saved proposals. Resolve failed temporary-chat cleanup before continuing. Reload does not send requests; each selected name uses a separate DeepSeek request with bounded name-matching excerpts.

## Сгенерировать анкету одного персонажа

В редакторе карточки нажмите **«Сгенерировать анкету»**. Это не подготовка всего состава: запрос касается только имени и четырёх текстовых полей этой карточки. Для нового персонажа сначала укажите имя и, если нужно, исходное условие — например, **«подруга Миры»** в **«О персонаже»**.

- **Сначала найти по истории** — получить факты из доступных выдержек и лора. Недостающие поля запрашиваются отдельно как новые предложения с пометкой **«Придумано»**. Противоречия не заполняются выдумкой.
- **Придумать анкету** — предложить новые данные с учётом мира и уже введённых условий. Связь с Мирой не меняет её анкету и не создаёт сыгранные события.

Предложение можно редактировать, включая всё, что помечено **«Придумано»**. После правки показывается **«Изменено вами»**; цитаты по истории относятся к исходному варианту. Заполненные поля не выбраны автоматически: отметьте нужные замены, нажмите **«Перенести выбранное в поля»**, затем **«Сохранить персонажа»**. Только последнее действие сохраняет анкету мира. Принятые тексты передаются как сведения о персонаже в последующих игровых запросах, когда его карточка попадает в контекст; они имеют приоритет над старыми описаниями. Автоматическое обновление сцены не переписывает их. Старые сообщения и самостоятельные записи лора остаются прежними.

Контекст ограничен, поэтому отсутствие найденных сведений не доказывает отсутствие персонажа во всей истории. Изображения, числа, отношения, роль главного героя и текущая сцена этой кнопкой не генерируются. Служебное видимое окно и последовательная очередь такие же, как у отдельных палочек; найденные цитаты не гарантируют правильность пересказа.

### Generate one character profile

In the character editor, click **Generate profile**. Enter a name and any known details first — for example, **Mira’s friend** in **About**. **Find in history first** retrieves available facts, then requests only missing fields as suggestions marked **Invented**. Conflicts are not replaced with inventions. **Invent a profile** creates suggestions using your seed and setting without changing other characters or advancing the story.

Edit any suggestion before accepting it. **Edited by you** distinguishes your revision; source quotes refer to the original suggestion. Existing fields are unselected unless you choose to replace them. Click **Insert selected into fields**, then **Save character**. Accepted text becomes the shared world profile and is sent as character information when that profile is relevant in future game context. Manual profile facts take precedence over older descriptions, and normal scene updates do not overwrite them. Old messages and separate lore entries are not rewritten. Context is bounded; model accuracy still needs review. The button does not generate images, stats, relationship progress, protagonist status or scene state.

## Палочки: найти сведения или предложить новое

Палочка у текстового поля открывает выбор без отправки запроса:

- **Заполнить по истории** — попросить сведения о персонаже из доступного разговора, выбранного лора и текущей анкеты. Ответ проверяется по точным цитатам; их можно раскрыть под полем. Если сведений недостаточно или модель сообщает о противоречии, поле не меняется. Проверка цитат не доказывает правильность пересказа: посмотрите текст и выдержки перед сохранением.
- **Предложить новое описание** — получить новые подходящие детали без противоречия известным фактам. Это предложение, не сыгранное событие.

Оба режима работают в отдельном временном чате. При доступном точном ID видимой реплики расширение читает связанную с ней цепочку из ответа истории DeepSeek. Раннее описание может попасть в запрос, даже если уже не видно на странице. Связи не угадываются по тексту, порядку списка или единственному последнему ответу. Служебные пары исключаются по точному родителю; размышления/неизвестные виды фрагментов не передаются. Если ID/связи/чтение недоступны, используются видимые реплики с пояснением об ограничении. Это не подтверждение завершённости или выбранности ответа и не автоматическая запись хроники.

Передаётся не вся история: до 40 выдержек общим размером 48 000 символов JSON, с приоритетом упоминаний имени/псевдонимов и слов нужного поля; одна длинная реплика ограничивается выдержкой. Читается одно полученное окно истории, без обхода следующих страниц. Модель может не найти сведения, особенно при одинаковых именах, косвенных описаниях или очень длинной истории. Запрос также содержит текущий несохранённый черновик и разрешённые записи текущего мира/книги. Исключённые записи памяти не добавляются повторно. Текст и цитаты не сохраняются в открытом session-хранилище.

Изменения становятся частью **анкеты мира** только после **«Сохранить персонажа»**. Старые сообщения и отдельные записи лора не переписываются автоматически. Ручные факты анкеты имеют приоритет при передаче карточки модели. План иллюстрации сохраняет собственный формат и не использует режим извлечения фактов.

Можно выбрать несколько палочек в одном редакторе: они выполняются по очереди, каждая в отдельном временном чате. Под полем показаны место в очереди и **«Отменить запрос»**. Следующий запрос получает актуальную несохранённую анкету, включая принятый результат предыдущего. Ручная правка ожидающего поля отменяет его запрос до отправки; правка активного поля сохраняется, а предложение появляется отдельно. Запросы не повторяются автоматически.

Следующее поле запускается после подтверждённого окончания очистки предыдущего чата. Если удаление завершилось ошибкой, показывается предупреждение и ссылка; если окончание очистки неизвестно, очередь останавливается. Закрытие редактора, смена чата/мира/книги или блокировка сейфа отменяют ожидающие запросы и прекращают применение активного. Очередь хранится только в памяти этого редактора; после перезагрузки не восстанавливается. Это не общая очередь всех вкладок и других инструментов: занятый слот в другом месте останавливает оставшиеся выбранные поля, не отправляя их повторно.

### Field wands: retrieve facts or suggest something new

Clicking a field wand opens a choice without sending a request. **Fill from history** requests established information from available conversation, selected lore and the current draft. Exact supporting quotes are checked and can be expanded below the field. Missing information or a reported conflict leaves the field unchanged. Quote validation does not prove a paraphrase is correct: review the text and excerpts. **Suggest a new description** permits fitting new details while preserving known facts; it is a suggestion, not a played event.

Both modes use an owned temporary chat. When an exact visible message ID and explicit native parent links are available, an on-demand history read retrieves older excerpts from that anchored path. No ancestry is inferred from similar text, list order or a unique leaf. Old service pairs are excluded by their exact parent; reasoning and unknown fragment kinds are omitted. Otherwise only visible messages are used, with a limitation notice. This does not prove reply completion/selection and does not enable automatic story ingestion.

Context is bounded to 40 excerpts / 48,000 JSON characters, prioritizing names/aliases and field-related terms. Long turns may be excerpted; only the received history window is read, without pagination. Indirect descriptions, ambiguous names or long histories can still be missed. The unsaved profile and allowed current-world/book memory are included; manual exclusions remain respected. Text and quotes are ephemeral, not written to plaintext session storage. Changes enter the world profile only after **Save character**; old messages and separate lore entries are not rewritten. Manual profile facts take precedence when the profile is sent. Image planning retains its separate format.

Select multiple field wands in one editor to queue them. Each runs in its own temporary chat, with its queue position and **Cancel request** shown below the field. The next request uses the current unsaved profile, including an applied previous result. Editing a queued field cancels it before dispatch; editing an active field preserves your text and shows the suggestion separately. Requests are never automatically repeated.

The next field waits until the previous worker has settled cleanup. Failed deletion shows a warning/link; unconfirmed cleanup stops the queue. Closing the editor, changing chat/world/book or locking storage cancels waiting requests and prevents applying the active result. The queue is editor-local and memory-only, not restored after reload or shared across tabs and other tools. A busy lane elsewhere stops the remaining selections rather than resending them.

## Хранение фотографий без лишних копий в памяти

Портреты, фотографии библиотеки и готовые селфи хранятся отдельно от анкеты, без изменения исходных пикселей. Старая библиотека переносится автоматически, по одной анкете; привязки к действиям, селфи и постоянным референсам сохраняются. При изменении имени или текста анкеты неизменные фотографии не передаются повторно. Новые файлы обрабатываются и сохраняются по одному, а в черновике остаются короткие ссылки.

Библиотека загружает видимые превью; при уходе изображения за пределы видимой области временная копия освобождается. Увеличение открывает оригинал. Сейф шифрует отдельные фотографии вместе с анкетами; блокировка не позволяет прочитать их. Экспорт мира и резервная копия по-прежнему включают все назначенные и неназначенные фотографии прямо в JSON, а не ссылки, требующие исходного устройства. При экспорте оригиналы читаются последовательно, но итоговый JSON и шифрование больших копий всё ещё требуют памяти. Отдельный огромный исходник тоже может превышать возможности браузера: отсутствие лимита библиотеки не означает бесконечную оперативную память.

### Separate photo storage

Portraits, library photos and ready-made selfies are stored separately from character profiles without changing their original pixels. Existing profiles migrate one at a time, preserving action assignments, selfie collections and pinned reference identities. Name/text-only saves do not resend unchanged photos; new files are stored individually and the draft keeps short immutable addresses. Only visible previews are loaded, temporary image URLs are released when they leave view, and the full-size viewer loads the original. The vault encrypts separate photos and denies locked reads. World exports and backups still embed every assigned/unassigned photo in portable JSON, not device-local addresses. Export reads originals sequentially, but the final JSON and encryption still need memory; a single huge image can also exceed browser resources.

## Действия и переименование

Действиями считаются и позы, и выражения лица, и реакции: «Сидит», «Смеётся», «Смущается», «Спокойствие». DeepSeek получает список доступных действий и выбирает `state.action` после завершённого сюжетного ответа для каждого присутствующего персонажа и главного героя. Учитываются обе стороны взаимодействия: «Даёт себя обнять» подходит принимающему персонажу, только если ответ подтверждает принятие и продолжающееся объятие. Отказ, намерение или уже закончившееся действие не должны включать этот портрет. Сам текст сообщения не принуждает к обновлению без корректного ответа модели.

В **Настройки → Персонажи** нажмите карандаш у названия → новое название → **Готово** → **Сохранить действия**. Фотографии, их варианты, ограничения и сохранённые состояния в чатах этого мира переезжают на новое имя одной операцией. Повторная загрузка не нужна. Совпадающее название выбрать нельзя, `neutral` защищён как запасной портрет. Массовое удаление строки отвязывает картинки, но сохраняет их в библиотеке; для переноса используйте карандаш.

Прежние поля `emotion`, `characterEmotions` и `blockedEmotions` читаются совместимо; новые записи и запросы используют действия. Пользовательские названия, лор и пиксели фотографий автоматически не переписываются.

## Подготовить всех персонажей из лора

При создании или импорте мира включён пункт **Подготовить персонажей из лора**. DeepRole открывает отдельную неактивную вкладку с новым пустым чатом DeepSeek, передаёт сохранённый лор частями и просит подготовить анкеты всех персонажей, включая ГГ, характеристики, доверие, симпатию, границы и уже произошедшие важные события. Нужен вход в DeepSeek; отдельный API-ключ не требуется.

Новый служебный чат получает лор из выбранного мира, а не из истории сюжетной вкладки. В новых запусках персонажи запрашиваются по одному, друг за другом. Если модель нарушит формат, один запрос исправления укажет конкретные структурные ошибки: например, пропущенное состояние или объекты вместо ID событий. Некорректные данные не подставляются в анкеты автоматически; формат и цитаты из источников проверяются строго. Ошибка подготовки и невозможность удалить служебный чат — разные проблемы, даже когда показаны вместе.

The new service chat receives lore from the selected world, not from the story tab's conversation history. New preparations request one profile at a time; existing older batches of up to two remain supported. One format-correction request identifies local structural errors, such as a missing state or milestone objects where string IDs are required. Invalid output is never silently filled in or applied; schema and exact source evidence remain strictly checked. Preparation failure and temporary-chat deletion failure are separate issues even when displayed together.

Готовые анкеты появляются для проверки: выберите персонажей и главного героя, при необходимости поправьте текст и числа, затем нажмите **Сохранить выбранных**. Числа — оценка по истории; рядом видны объяснение и цитаты источников. Близость определяется по доверию и симпатии. Неизвестные факты не должны выдумываться. Заполненные ранее поля, изображения и значения с журналом и блокировками в сыгранных чатах сохраняются. Новые анкеты, стартовые настройки и текущий прогресс принадлежат игре этого лора. Смена чата не сбрасывает сыгранные значения.

Мини-окно палочки появляется справа от панели персонажей, на уровне её верхнего края. Если места мало — оно остаётся в пределах экрана. Потяните за заголовок, чтобы переместить его, или используйте стрелки при фокусе на заголовке; кнопка со стрелкой возврата снова ставит его рядом с панелью. Показываются реальные этапы, лёгкая анимация ожидания и меняющиеся подсказки — без выдуманных процентов. Системная настройка уменьшения движения учитывается.

Новые запуски готовят по одному персонажу за ответ; каждая проверенная анкета сохраняется до следующего запроса. Уже начатые старые партии до двух персонажей остаются совместимыми. Даже если DeepSeek оборвёт общий JSON или заменит ответ плашкой отказа, полностью полученные объекты отдельных персонажей сохраняются после проверки формата и цитат источников. Незавершённые поля не дописываются; размышления и не полученный браузером текст не используются. При ошибке можно проверить и явно сохранить готовые анкеты либо продолжить подготовку остальных после удаления временного чата. Продолжение использует прежние результаты только при неизменном лоре. Снимок привязан к заданию, шагу, чату и ответу, защищён сейфом и не входит в экспорт мира или резервную копию; после завершения или отмены он удаляется. Промпты для обхода отказа не отправляются, ответ на сервере не переписывается.

После получения результата DeepRole удаляет только свой временный чат через меню DeepSeek и закрывает служебную вкладку. При ошибке удаления результат не теряется: появятся **Повторить удаление** и ссылка на временный чат. Если вы начали вручную редактировать служебный чат, автоматизация остановится. В пустом мире подготовка ждёт первого лора; для существующего мира используйте **Создать персонажей из лора** в разделе «Лор» или палочку в заголовке панели персонажей.

Окно подготовки можно скрыть крестиком или клавишей **Escape**, когда фокус находится внутри окна. Палочка в панели персонажей вернёт его. Скрытие сохраняется после обновления страницы, не отменяет подготовку и не удаляет результат. Если временный чат уже удалён вручную, нажмите **Чат уже удалён**: DeepRole снимет старую отметку об ошибке удаления и разрешит повторную подготовку. Кнопка не удаляет чаты, анкеты, аватарки или лор и доступна только после завершения либо отмены подготовки. Готовые анкеты можно проверить даже при ошибке удаления временного чата.

**Открыть временный чат** показывает уже существующую служебную вкладку. Если она закрыта, открывает сохранённый адрес того же диалога в новой вкладке браузера — без нового промпта и повторной подготовки. Адрес берётся из реально созданного чата, включая его путь `/a`; служебные метки запуска не переносятся. Для старых заданий с сохранённым ID используется обычный адрес DeepSeek `/a/chat/s/ID`. Если достоверного ID нет, кнопка недоступна с пояснением: пустой чат вместо прежнего не создаётся. Уже удалённый на сервере диалог восстановить этой кнопкой нельзя.

Общего потолка состава нет. Защитные пределы отдельной операции сохраняются: до 12 участников одной сцены, шесть числовых характеристик на карточку, восемь событий отношений и 220 тысяч символов источников одного разбора. Портреты в DeepSeek не отправляются. При изменении лора во время подготовки сохранение остановится и предложит повторный разбор.

## Понятный редактор

Откройте персонажа и выберите вкладку:

- **Анкета** — постоянные сведения для всех чатов этого мира.
- **В сцене** — действие, состояние, цель, отношения и показатели общей игры этого лора.
- **Отношения** — отдельные числовые доверие и симпатия, исходное отношение, границы, условия сближения и журнал. [Как настроить систему](RELATIONSHIPS.ru.md).
- **Изображения** — портреты, действия и библиотека. Загрузите пачку, выделите картинки и назначьте действия. Небольшие пачки выделяются сразу.

Правки сохраняются при переходе между вкладками. Сохранение оставляет окно открытым; если нужное поле не заполнено, редактор покажет его. **Добавить действие** в разделе изображений сразу добавляет название в мир; картинки нужно отдельно сохранить кнопкой **Сохранить персонажа**. Названия не переводятся автоматически.

В **Настройки → Персонажи** действия видны отдельными элементами: добавьте название или уберите ненужное. «Редактировать списком» оставлено для массовых правок. Удаление из списка не удаляет портреты.

Все панели под названием чата одной ширины — 224 px по умолчанию. Кнопка ширины рядом с «Вместе» и ползунок в **Настройки → Приложение → Панели и сцена** меняют её сразу у всех (200–360 px). Сужение окна не перезаписывает настройку.

## Генерация текста для поля

Небольшая кнопка с волшебной палочкой рядом с описанием, характером, целями, сведениями о персонаже, состоянием в сцене, границами, реакциями, поведением на стадиях отношений, условиями событий, описаниями показателей и ситуаций для селфи просит DeepSeek заполнить только это поле. Она использует текущую несохранённую анкету, разговор и доступную память мира. Изображения в запрос не отправляются.

Служебный запрос отправляется в отдельный временный чат в видимом окне с плашками DeepRole. Игровой чат и его черновик не меняются. Оставьте служебное окно видимым: после ответа расширение проверяет результат и пытается удалить только свой временный чат, затем закрыть окно. Сокрытие настоящего запроса/размышлений/JSON действует на экране, не скрывает данные от DeepSeek. Готовый текст появится в выбранном поле, но станет частью анкеты только после **Сохранить персонажа**; при проблеме очистки появится отдельное предупреждение.

Если во время ожидания вы изменили выбранное поле или начали сохранение, новый вариант показывается отдельно для копирования. Правки остальных полей сохраняются. Ошибка, отказ DeepSeek или превышение длины поля не заменяют прежний текст. Нажатие на название поля больше не фокусирует его и не переключает соседнюю настройку; сам элемент и управление с клавиатуры работают как прежде.

## Включить за минуту

1. Подключите мир к открытому чату.
2. Карточки включены по умолчанию. Если раньше отключали их, включите **Настройки → Персонажи → Карточки персонажей**.
3. Под индикаторами контекста появится компактный список имён, ролей и действий, без изображений. В **«В сцене»** видны герой и присутствующие участники, в **«Все»** — весь список с поиском. Имя открывает анкету, **+** добавляет персонажа. Кнопка раскрытия рядом с **+** открывает по центру галерею всех персонажей с портретами; карандаш открывает редактор в этом же окне. Сохранение оставляет редактор открытым. Кнопка «К персонажам» возвращает в галерею, поиск остаётся прежним.
4. В своей карточке отметьте **Мой главный герой**. Плавающие портреты по умолчанию располагаются по сторонам вариантов: герой слева, собеседники справа. Если места достаточно, говорящие стоят рядом в одном размере, а присутствующие, но молчащие персонажи — рядом с ними на 15% меньше; между портретами 6 пикселей, нижние края выровнены. При смене собеседника меняется и порядок. На тесном экране портреты перестраиваются, не перекрывая варианты. Они остаются на месте во время следующего ответа и обновляют действие после него.
5. Продолжайте обычный разговор. После ответа DeepSeek автоматически обновляет действие, состояние, ближайшую цель, отношения и показатели, если прислал корректные изменения. Если обновления нет, сохраняются прежние значения — расширение не придумывает их самостоятельно.

При создании и импорте мира включён пункт **Подготовить персонажей из лора**: отдельный служебный чат запрашивает весь состав, анкеты и начальные показатели. Перед сохранением результат можно проверить. Пустой мир ждёт первого сохранённого лора; при отключённом пункте используйте палочку в панели персонажей, команду в разделе «Лор» или добавьте карточку кнопкой **+**. Карточки разрешают автоматически сохранять состояние персонажей из ответов; их можно отключить. Обычное **«Обновить лор»** по-прежнему требует вашего подтверждения.

## Аватарка главного героя

У карточки героя должна быть отметка **Мой главный герой**. DeepSeek получает его имя, доступные названия портретов и явное правило: ваши игровые реплики и действия относятся к нему, а состояние героя нужно возвращать вместе с обновлением сцены. Для речи используется подходящая разрешённая поза, например ваша **Разговаривает**; мысли, действия, команды вне игры и цитаты прошлых сцен не считаются речью автоматически.

Действие меняется после завершённого ответа с корректным обновлением. Сам ввод текста и выбор ещё не отправленного варианта аватарку не меняют. Для видимой смены загрузите портрет к нужному действию и оставьте его в списке действий мира; без изображения действует обычный нейтральный портрет. Личные запреты действий сохраняются. Герой не становится собственным собеседником.

## Селфи по контексту

В панели **Персонажи** нажмите **Попросить селфи**, либо попросите персонажа обычной репликой в чате. Рядом видна текущая готовность. В **Анкета → Изображения → Селфи из генератора → Как сблизиться** показаны характерные реакции, границы и последнее изменение отношений. Кнопка не перезаписывает введённый черновик.

В анкете **Изображения → Постоянный референс** загрузите лицо персонажа либо закрепите картинку из его библиотеки. Доступны два образа: **Нейтральный** и **Пикантный**, каждый с необязательной подсказкой, когда он подходит. DeepSeek выбирает по сцене, при отсутствии нужного образа используется нейтральный или текстовая внешность. Привязка хранится по персонажу из общего списка, поэтому изменение имени её не сбрасывает. **Создать иллюстрацию** работает одним кликом: скрытое описание кадра → индикатор → изображение 16:9; селфи генерируются в 9:16. Необязательный стиль задаётся в настройках изображений. **Попробовать ещё раз** использует прежние модель, описание, параметры и референсы; нового запроса к DeepSeek нет. Список готовит существующая команда **Подготовить персонажей из лора**; новые люди также могут добавляться из сцен. Для Qwen Image Edit выберите эту модель в **Настройки → Изображения → Модель для референсов** своего подключения. Без референса используется обычная модель генерации: постоянная внешность из анкеты и описание фактического кадра от DeepSeek. Если анкета ещё пуста, DeepSeek может описать внешность на основе предоставленного лора. Это не переписывает сохранённый лор.

В **Селфи из генератора** выберите готовность: **По решению персонажа**, **Когда комфортно общаться** или **В близких отношениях**. Точные числа скрыты под **Точные показатели и пороги**. Достигнутый уровень не гарантирует согласия.

Селфи бывают двух видов: **готовый снимок без генерации ИИ** и **новое фото от отдельно включённого генератора**. Оба вызываются вашей просьбой — кнопкой **Попросить селфи** либо сообщением в чате. В готовой подборке DeepSeek только отыгрывает согласие/отказ и выбирает категорию: новую картинку он не рисует, сервис генерации при показе готового фото не используется. Генератор требует подключения/ключа API и может быть платным. Разница объясняется непосредственно во вкладке **Изображения**.

Необязательные **Готовые подборки селфи** сохраняют прежние фото: название, описание подходящей ситуации и тот же понятный выбор уровня. Например, «Дома» — вечером в повседневной одежде; «Прогулка» — на улице днём. **Добавить фото** загружает файлы, **Выбрать из библиотеки** открывает изображения только этого персонажа. Можно отметить несколько, включая назначенные действиям и постоянные референсы, и нажать **Добавить выбранные**. Прежние назначения не меняются, дубликаты не добавляются. Уже имеющиеся в подборке фото помечены; выбор можно отменить кнопкой или Escape. Удаление из подборки не удаляет источник из библиотеки. Одна **Обычная категория** служит запасной, когда сцена не подходит к остальным. Сохраните подборки кнопкой **Сохранить персонажа**. До сохранения это черновик. Поддерживаются и ранее назначенные действия «Селфи», «Селфи: дома», «Selfie».

Просьба отправить селфи — обычная реплика. DeepSeek получает описание подборок и сам отыгрывает согласие или отказ. При настроенном учёте отношений с главным героем расширение дополнительно проверяет сохранённые доверие и симпатию: по умолчанию не ниже 40/30, пороги редактируются для каждой категории. При выключенном учёте числовой барьер не применяется; учитываются отношения в истории. Достигнутый порог разрешает возможность, но не обязывает персонажа соглашаться. Правки чисел в этом же ответе не обходят проверку предыдущего сохранённого состояния.

Фото появляется только после корректного события отправки в завершённом ответе. Для готовой подборки задержка около 1,5 секунды; расширение выбирает локальную фотографию, избегая немедленного повтора. Если подходящей подборки нет, используется обычная. При отсутствии подходящих загруженных фото и включённой генерации DeepSeek описывает селфи, а расширение отправляет текст и закреплённый референс выбранному сервису изображений. Скорость готового результата зависит от сервиса; в ответе отображается ожидание. DeepSeek не получает изображения или ключ провайдера. Генерация оплачивается по тарифу подключения. Отказ, обещание на потом, служебный запрос и варианты действий фото не создают.

Фото остаётся за конкретным сообщением, включая reload и виртуализацию истории. Полная резервная копия сохраняет эти привязки; экспорт мира переносит подборки, но не историю сообщений. После удаления исходного фото показывается пояснение вместо подстановки другого изображения. Блокировка сейфа убирает фото с экрана. Состояние генерации сохраняется: перезагрузка не создаёт ещё один оплаченный запрос. После ошибки доступен только ручной повтор; после неопределённого таймаута провайдер мог обработать исходный запрос. Разрешение загрузить готовый результат с другого домена не повторяет генерацию. Импорт резервной копии сам не запускает оплаченные задания: разрешение автоматического запуска хранится только в текущем сеансе браузера.

Аватарки в галерее, редакторе и сцене, а также фото в ответе раскрываются по нажатию. Колёсико и +/− увеличивают до 128×; перетаскивание перемещает картинку, уменьшение останавливается на вписанном размере. Кнопки 100% и «Вписать», клавиши 0 / F / Escape доступны отдельно. Имя плавающего портрета открывает анкету. Просмотр не восстанавливает утраченное исходное разрешение.

## Исправить постоянный факт

Откройте карточку персонажа → **«Изменить постоянный факт»** и напишите, что должно быть верным теперь: например, «У Миры теперь чёрные волосы вместо рыжих». Перед запросом сохраните незаконченные правки карточки. DeepRole просматривает **все записи лора подключённого мира**, даже без имени персонажа, и передаёт их DeepSeek вместе с текстовыми полями его анкеты. Ответ — предложения в JSON, не исполняемый код. В окне проверки видно «было → станет» для каждой записи и изменённых полей анкеты; по умолчанию ничего не выбрано. Выберите нужное и подтвердите сохранение. Записи заменяются по их ID, новые дубликаты из этого запроса не создаются. Если мир или запись успели измениться, вся операция отклоняется без частичного сохранения; последнюю подтверждённую правку можно отменить, пока её записи не редактировали снова. Портреты, действия, роли и состояния чата не меняются.

Для одного запроса сейчас поддерживается до 100 записей и 60 000 символов текста лора. Если мир больше, DeepRole не отправляет частичный список и не утверждает, что проверил всё: покажет ошибку, а записи останутся прежними. Модель может пропустить косвенное или неоднозначное упоминание даже при полной проверке; внимательно просмотрите предложения. Прежний факт в старых сообщениях DeepSeek не удаляется, но исправленная память будет использоваться в следующих запросах, когда запись попадёт в контекст.

### Better Deepseek (BDS), карточки и старый ответ

[Better Deepseek (BDS)](https://github.com/EdgeTypE/better-deepseek) переносит названия, текст и режимы записей. Его JSON не содержит отдельных анкет и портретов DeepRole, даже если записи подробно описывают персонажей. При включённом пункте **Подготовить персонажей из лора** импорт запускает отдельный разбор записей с проверкой предложенных карточек. Существующий мир можно разобрать палочкой в панели персонажей. DeepSeek также может создать карточки участников после новой реплики с подключённым миром; неизвестные факты остаются пустыми, а результат большого разбора следует проверить.

Новый импорт создаёт отдельный экземпляр мира с новым внутренним ID. Проверка **не сравнивает сюжет или имя файла**: старое обновление должно принадлежать выбранному миру, этому чату и актуальной версии карточек. У нового ответа проверяется связь с действительно отправленной репликой расширения. Поэтому предупреждение касается только обновления карточек из старого ответа, а не правильности вашей истории или потери памяти. Не переназначайте старые данные на новый мир наугад; продолжите историю с выбранным миром.

Портреты загружаются в анкеты и хранятся в вашей библиотеке, не в коде расширения. **Экспорт мира DeepRole** переносит анкеты и их изображения. **Полная резервная копия** дополнительно сохраняет привязки чатов, состояния сцены и расстановку. Файл Better Deepseek (BDS) не заменяет такую копию. Библиотеки разных браузеров независимы.

Если участники сцены ещё неизвестны, показываются все персонажи с коротким пояснением. Фильтр меняет только экран, не память и не состав отправляемого контекста. При переходе в другой чат или мир снова открывается «В сцене», прежний поиск очищается.

У каждого браузера своя локальная библиотека. Один и тот же чат DeepSeek в Brave и браузере Codex не означает общую память DeepRole. Повторный импорт файла создаёт отдельную копию мира: ответ для прежней копии не переносится в новую. Продолжите чат с выбранным миром, чтобы DeepSeek вернул обновление именно для него.

В новых обычных репликах мир и чат определяет само расширение перед отправкой. DeepSeek возвращает метку этой реплики и имена персонажей, а не выбирает копию мира. Поэтому старые названия и служебные поля в истории не перенаправляют обновление в другую библиотеку. Если вы действительно сменили мир или вручную изменили карточки во время ответа, запоздалое обновление не применяется. Ответы, полученные до установки новой версии или отправленные другим браузером, автоматически не переносятся: нужна следующая обычная реплика из текущего браузера. Изображения между браузерами этим механизмом не переносятся.

## Одна картинка для нескольких действий

Названия встроенных действий переведены только для удобства: **Радость · happy** — одна и та же действие с ключом `happy`. В настройках видны ключи; DeepSeek выбирает их из разрешённого списка. Свои названия можно писать на русском или английском, но автоперевода и автоматического объединения синонимов нет. `смех` и `laughing` — разные ключи. `screaming/shouting/scarry` или названия через запятую считаются одной записью, а не списком синонимов.

Чтобы несколько действий показывали одну картинку:

1. Во вкладке **«Изображения»** добавьте нужные названия через **«Добавить действие»**. Можно также использовать **Настройки → Персонажи**.
2. Откройте **Библиотеку изображений** в карточке, выделите картинку или несколько вариаций.
3. Выберите основную действие, раскройте **«Ещё действия для этих картинок»** и отметьте остальные.
4. Нажмите **«Назначить действия»**, затем **«Сохранить персонажа»**.

Любое из выбранных действий получит те же изображения. Назначение добавляет их к существующим вариациям, не заменяет старые. Это не постоянная связь наборов: последующие добавления назначайте тем же действиям снова. У каждого действия свой цикл вариаций. Правильный выбор действия зависит от ответа DeepSeek; расширение не распознаёт действия по картинке.

После сохранения редактор остаётся открытым и показывает **«Сохранено»**. Можно сразу загрузить следующую картинку и сохранить ещё раз. Окно, выбранная действие и раскрытая библиотека не сбрасываются. **«Закрыть»** или **«К персонажам»** закрывают редактор отдельно. Неизменённые поля сохраняют свежие обновления сцены, а конкурирующие правки того же поля не перезаписываются молча.

## Доступные действия персонажа

### Палочки отдельных полей

Палочка возле внешности, характера, целей и других текстовых полей теперь создаёт отдельную неактивную вкладку DeepSeek. В новый временный чат передаются редактируемая анкета, подходящие включённые записи текущего мира и ограниченный фрагмент видимого разговора — без размышлений и фотобайтов. Это не вся история: перед сохранением проверьте предложение. Ручные исключения памяти сохраняются; сам явно редактируемый черновик анкеты передаётся как исходные данные.

Основной разговор и набранное сообщение не меняются. Готовый текст подставляется в неизменённое поле, но не сохраняется в лор автоматически. Если вы успели изменить поле, предложение остаётся отдельно. После результата расширение удаляет только созданный им чат и закрывает только свою вкладку. Если удаление не подтверждено, готовый текст остаётся, а рядом появляется предупреждение и ссылка для ручной проверки. При вашем вмешательстве во временный чат автоматические действия останавливаются.

Перезагрузка служебной вкладки не отправляет запрос повторно. Перезапуск фоновой части расширения прерывает незавершённую подготовку: текст запроса/ответа хранится только в оперативной памяти, не в открытых session-метаданных. После ошибки можно явно повторить запрос. Служебные сообщения прежних версий в игровом чате не удаляются; перенос не меняет их старые статусы. Анализ памяти и продолжение истории — другие операции и пока остаются на прежнем пути.

The wands beside appearance, personality, goals and other text fields now use a separate inactive DeepSeek tab. The temporary chat receives the current unsaved character draft, relevant enabled lore from the selected world and a bounded visible conversation excerpt, without reasoning or image bytes. Manual memory exclusions are respected; the explicitly edited draft remains input. Review the suggestion: this is not the whole conversation.

The game chat and its message draft are untouched. Suggestions are not automatically saved as lore. If you edit the field while waiting, the suggestion stays separate. Only the extension-owned chat and tab can be cleaned up. Failed deletion preserves valid text and shows a warning with a safe link; human interaction stops automatic operations. Reloads never resend a request. A background restart interrupts ephemeral field preparation rather than persisting lore in session metadata. Older service messages are not deleted. Memory analysis and story continuation are separate, unchanged operations.

В карточке откройте **Изображения → Доступные действия**: переключатели сразу раскрыты. Выключите ненужные действия и нажмите **Сохранить персонажа**. По умолчанию разрешены все действия мира; есть поиск, **Разрешить все** и **Только спокойствие**. Тот же список остаётся в **Анкета → Доступные действия** и в **Лор → Мир и профили**, даже без подключённого чата.

Правило общее для всех чатов этого мира. Новые названия действий разрешены автоматически; удалённые из списка мира названия сохраняют запрет в разделе **Вне списка мира**, пока вы не снимете его. `neutral` — **Спокойствие** — всегда доступно. Если текущее действие стало запрещённым, карточка и игровой портрет используют спокойствие; остальные сведения не меняются.

DeepSeek получает персональный разрешённый список. Если он всё-таки вернёт запрещённое действие в коде карточки, DeepRole оставит прежнее допустимое действие или выберет спокойствие, но примет остальные корректные поля. Модель не может снять запрет. Это защищает действие и портрет карточки, но не гарантирует отсутствие такого действия в сюжетном описании.

Выключение сразу снимает все портреты с этой действия в редакторе, а сохранение применяет изменения. Картинки не удаляются: они остаются в библиотеке персонажа, а назначения другим действиям сохраняются. Выключенная действие недоступна для загрузки и назначения изображений. Повторное включение не восстанавливает старые привязки: назначьте нужные картинки из библиотеки заново. Если картинка просто отсутствует, запрещать действие не нужно: используется обычный портрет или силуэт. Экспорт мира и полная резервная копия переносят правило и оставшиеся картинки.

Удаление действия из списка мира с последующим **Сохранить действия** также автоматически снимает его портреты у всех персонажей этого мира, убирает устаревшие циклы и возвращает действие к спокойствию в его чатах. Другие миры не меняются. Общий список применяется только к мирам без собственного списка действий. Старые ошибочные привязки исправляются при сохранении списка мира или карточки персонажа. Число изображений в библиотеке не ограничивает отвязку; картинки не теряются.

## Сохранение анкеты и сцены

Можно отметить **Мой главный герой** и загрузить портреты до одного нажатия **Сохранить персонажа**. Если за это время сцена обновится, портреты сохранятся, а свежие поля, которые вы не редактировали, останутся актуальными. Если одно и то же поле или набор изображений одному действию изменены одновременно в двух местах, появится предупреждение; несохранённые правки останутся в открытой форме.

**Анкета мира** — имя, внешность, характер, цели, справка и портреты. Она общая для чатов, использующих этот мир. Эти поля редактируете вы; очередной ответ не перезаписывает существующую анкету. DeepSeek может создать нового персонажа с коротким описанием, если он действительно появился в истории. Персонажи видны также среди профилей и на карте.

**Сейчас в этом чате** — действие, состояние, ближайшая цель, текстовое описание отношений, до шести показателей и присутствие в сцене. Эти данные сохраняются между посещениями. Обычный новый чат не наследует их; «Продолжить в новом чате» переносит локально сохранённую сцену в пустую ветку того же мира. Неизвестные текстовые значения остаются пустыми.

Во вкладке **Отношения** отдельно настраиваются две шкалы 0–100. Система включена по умолчанию, но не угадывает числа для старых персонажей. Вы задаёте начало; DeepSeek может предложить небольшие изменения после сыгранного события, а расширение проверяет запрос и цитату. Значения можно менять и фиксировать вручную. Подробности, условия сближения и перенос прогресса — в [справке об отношениях](RELATIONSHIPS.ru.md).

Под портретом первые два заполненных показателя в порядке анкеты, например «Энергия: Отдохнула», появляются при наведении мыши на персонажа или фокусе с клавиатуры. На сенсорном экране они видны постоянно. Место под них сохраняется, чтобы портреты не сдвигались при наведении; компактная полоса по-прежнему скрывает подробности. Все шесть можно посмотреть и изменить по нажатию на портрет. Если показателей нет, пустые шкалы не появляются. Это уже сохранённые данные сцены, а не отдельный анализ: новых запросов или токенов не требуется. Они отражают ответ модели или вашу правку, не независимую проверку событий.

Ручные правки вступают в силу после **Сохранить персонажа**. Сохранённая анкета активного персонажа попадёт в следующий запрос. Исходный импортированный текст не переписывается и доступен в карточке отдельно. В инструкции модели новые поля имеют приоритет над прежним описанием — это указание модели, а не гарантия её ответа.

## Кто в сцене и кто разговаривает с героем

**В сцене** означает, что персонаж находится здесь. Его портрет остаётся виден, даже если он молчит или общается с другим персонажем. **Собеседник героя** означает, что он обращается к вашему главному герою. Можно отметить нескольких людей одновременно: у каждого будет подпись «Обращается к герою» и обычный размер портрета. Присутствующие молчащие участники показываются немного меньше, если автоматическая группа помещается у вариантов. Заданные вручную позиции и размеры сохраняются.

Например, Леон заговорил с охранником, а Мира осталась рядом: все трое сохраняют портреты. Если Мира и Леон вместе обращаются к герою, оба отмечаются собеседниками. Если никто не обращается к герою, участники всё равно видны, но без этой отметки.

Исправить список можно в редакторе → **В сцене** → **Сохранить персонажа**. Выбор собеседника также включает «В сцене». Снятие отметки собеседника не убирает персонажа из сцены и не снимает отметки с остальных. Главный герой не может быть своим собеседником. Следующий ответ DeepSeek обновляет список по истории; это не постоянное закрепление. Повторное открытие уже учтённого ответа не отменяет вашу правку.

## Расставить портреты

Портреты рядом с вариантами — отдельные элементы, без общего фона с кнопками выбора. Если они помещаются по бокам, от вариантов до портретов остаётся 24 px. При отправке новой реплики они не исчезают: прежняя сцена видна во время генерации, затем состояние обновляется по готовому ответу.

Одна маленькая кнопка в карточке вариантов закрепляет оба портрета по сторонам. Кнопка с булавкой удерживает сами варианты над полем сообщения при прокрутке; вместе с ними остаются видны и портреты. На узком экране портреты складываются над карточкой, чтобы не закрывать варианты. Те же настройки находятся в **Настройки → Приложение → Панели и сцена** и включаются независимо друг от друга.

- Перетащите **имя с ручкой ⠿**, чтобы переместить портрет в любое место экрана, в том числе за границы колонки чата.
- Потяните **нижний правый угол**, чтобы изменить размер, вплоть до всей высоты видимой области страницы. Изображение остаётся **3:4**; подписи и ручки тоже помещаются в экран. Предела 360 px больше нет. Ручное увеличение делает только этот портрет независимым от автоматической группы и закрепления — размер не сбрасывается. В узком окне карточка временно уменьшается, не теряя сохранённого размера; увеличенный портрет не прячется в компактный ряд. Сброс расстановки возвращает автоматическую группу.
- Нажмите **изображение**, чтобы открыть анкету, действия и все показатели.
- **Сбросить расстановку** возвращает обычное расположение в текущем чате. Общий сброс доступен в **Настройки → Персонажи**.

Расположение сохраняется автоматически после отпускания мыши — отдельно для каждого чата и мира. Оно привязано к персонажу и экрану, не к месту в списке: после перемещения портрет остаётся на выбранном месте при прокрутке. Перенос не меняет память и не отправляет сообщения DeepSeek. Ошибка сохранения возвращает предыдущую позицию. На ручке работают стрелки; Shift увеличивает шаг, Esc отменяет перетаскивание. Стрелки на угловой кнопке меняют размер. Портреты можно наложить друг на друга или на варианты; если это мешает, переместите их или сбросьте расстановку. Старые расстановки читаются без удаления; первое новое перемещение сохраняет экранную позицию.

## Портреты и действия

### Загрузить пачку и назначить действия позже

В карточке персонажа откройте **Изображения → Библиотека изображений → Загрузить в библиотеку**. Выберите сразу несколько файлов. Они появятся в разделе **Без назначения** — заранее распределять их не нужно.

Нажмите нужные миниатюры, выберите действие внизу и нажмите **Назначить действия**. Для другой действия можно выбрать другие картинки или повторно использовать те же из вкладки **Все**. Чтобы оставить распределение на потом, просто нажмите **Сохранить персонажа**: неназначенные картинки тоже сохранятся. Без этой кнопки изменения остаются черновиком.

Библиотека отдельная у каждого персонажа. Она переносится с экспортом мира и полной копией. Картинки не отправляются DeepSeek. Ограничений DeepRole на общий размер, число файлов и вариаций действия нет. Удаление вариации оставляет картинку в библиотеке; окончательно убрать неназначенную картинку можно корзиной.

Поле **«Найти эмоцию или действие»** перед назначением фильтрует основной список и **«Ещё действия для этих картинок»**. Можно вводить часть названия, стандартное русское/английское имя или своё название; регистр, лишние пробелы и `ё/е` не мешают поиску. Поиск не меняет назначения и не снимает выбор картинок или дополнительных действий. Уже выбранное основное действие остаётся в списке с пояснением, если не совпало с поиском; строка **«К назначению»** показывает весь набор. При отсутствии результатов очистите поиск кнопкой ×. Enter в поиске не сохраняет анкету; Escape сначала очищает непустой поиск.

**Image assignment search:** use **Find an emotion or action** to filter the primary action list and extra-action checkboxes. Partial custom names and standard Russian/English labels are matched without case sensitivity, extra spaces or the Russian `ё/е` distinction. Filtering preserves picked images and hidden selected actions; **Assigning to** lists all targets. A selected primary action remains explicitly marked when outside the search results. Clear × restores the list; Enter in search does not submit the character form and Escape clears a nonempty query first.

### Несколько изображений для одному действию

1. Выберите действие в карточке персонажа и нажмите **Добавить изображения**. Можно выбрать сразу несколько файлов. Поддерживаются PNG/JPG/WebP без ограничения числа файлов и их размера в DeepRole.
2. Миниатюра переключает предпросмотр, корзина под ней удаляет только эту вариацию. Повторная загрузка добавляет изображения, а не заменяет предыдущие. Нажмите **Сохранить персонажа**.
3. После принятого обновления сцены DeepRole выбирает следующий портрет из перемешанного набора. Внутри круга повторов нет; после всех изображений начинается новый круг, без одинаковых картинок подряд на границе кругов. У каждого действия свой круг. Один портрет остаётся неизменным.

Открытие галереи, перемещение, обновление страницы и повторный просмотр ответа не переключают вариацию. При смене действия используется набор нового действия, а при его отсутствии — набор neutral. Порядок сохраняется отдельно для каждого чата. Все вариации входят в экспорт мира и полную копию; текущий шаг круга — только в полную копию вместе с состоянием чата. Старые файлы с одним изображением продолжают работать.

### Перемещение и сворачивание панелей

Панели контекста, выбора мира, персонажей и блок управления держат между собой зазор минимум 1 пиксель, включая кнопки при наведении. Кнопки расположены сбоку от своей панели и не занимают отдельную строку между карточками. При перетаскивании панель занимает ближайшее свободное место. Старые перекрытия исправляются при показе; разворачивание панели и изменение размера окна тоже учитываются. Если экран слишком мал, панели собираются в прокручиваемую колонку; свободное перемещение возвращается, когда места достаточно. Плавающие портреты персонажей остаются независимыми.

Список персонажей по умолчанию уже. Потяните за саму панель контекста чата, памяти, персонажей, вариантов или мира, чтобы переместить её; отдельной ручки больше нет. Обычный короткий клик по кнопке внутри панели по-прежнему выполняет её действие. Маленькая кнопка **−** появляется при наведении на эту панель; на сенсорном экране она видна постоянно. Общая ручка над панелями видна всегда. Включите **Вместе**, чтобы перетаскивание любой панели перемещало всю группу; выключите для независимого перемещения. С клавиатуры выделите панель и используйте стрелки.

Свёрнутые панели собираются в один ряд значков. Нажмите значок, чтобы вернуть панель. Стрелка сброса возвращает начальную расстановку и разворачивает всё. Позиции и сворачивание сохраняются в этом браузере; на лор и токены не влияют. Ручки перемещения и изменения размера **портретов** появляются при наведении или клавиатурном фокусе; на сенсорном экране доступны постоянно.

В карточке откройте **Портреты и действия**, выберите **«Действие портрета»** и загрузите PNG, JPG или WebP. Для обычного состояния используйте **Спокойствие / neutral**. Редактор сначала показывает портрет для текущего действия. Переключение предпросмотра не меняет действие и не требует сохранения; само действие меняется выше, в разделе «Сейчас в этом чате».

Если нужной картинки нет или браузер не может её открыть, показывается обычный портрет, затем — выбранный мужской, женский или нейтральный силуэт. Сохранённые изображения при этом не удаляются; новое изображение можно загрузить для того же действия.

Под индикаторами — компактные имена и статусы. Крупные портреты доступны в центральной галерее и плавающем слое рядом с вариантами. В галерее нажмите карандаш, в плавающем слое — изображение, чтобы изменить анкету.

В **Настройки → Персонажи** можно сохранить свой список действий: одно в строке, до 32 вместе с `neutral`. Если в чате выбран мир, список сохраняется для этого мира. Без выбранного мира меняется общий список для миров без собственного списка. Новые названия передаются DeepSeek с последующим сообщением. Удаление действия и сохранение списка автоматически отвязывают его портреты, сохраняя картинки в библиотеке или других действиях. DeepSeek получает только активный список из настроек, без изображений.

Изображения хранятся локально. После выбора файлов открывается **Сжать изображения?**: **Без сжатия** сохраняет оригиналы без изменения размера и байтов; **Высокое качество** использует длинную сторону из **Настройки → Оформление → Качество загруженных изображений** (по умолчанию 1920 px, диапазон 256–4096); **Меньше места** создаёт WebP с качеством 82% и длинной стороной не больше 1280 px или меньшего значения из настроек. Для высокого качества подходящий оригинал не пересжимается, большие изображения уменьшаются в WebP с качеством 92%. Маленькие исходники не растягиваются. Выбор появляется для каждой загрузки; отмена не добавляет изображения. Уже загруженные картинки не меняются. Это общая настройка портретов, библиотеки, загружаемых референсов и селфи, не разрешение генератора API. DeepSeek получает название действия, **но не картинку**. Без отдельно включённой генерации переключаются только ваши готовые варианты.

Ползунок **Размер превью** в библиотеке меняет размер миниатюр от 96 до 280 px и запоминается отдельно от анкеты. В разделе референсов отдельный **Размер превью референсов** меняет обычное и альтернативное превью и сетку выбора; настройка сохраняется для следующих открытий, не меняя файлы, привязки или размер миниатюр библиотеки. Кнопка **Просмотр** открывает картинку без изменения выбора или действий. Настройка размера не создаёт несохранённых изменений персонажа. В экспорт мира входят сами сохранённые данные изображений: отдельная папка с файлами не нужна.

## Токены и надёжность

- Отдельных фоновых запросов нет. К обычной реплике добавляется инструкция; в конце обычного ответа DeepSeek возвращает небольшой блок изменений.
- В запросе — список имён, до шести актуальных анкет и компактное состояние остальных присутствующих, без повторения их анкет. Собеседники имеют приоритет. Байты картинок, размеры и координаты не передаются. Расход текста учитывается в индикаторе контекста и уменьшает оставшийся бюджет подбора памяти.
- Длинные анкеты всё равно стоят токенов. Пишите факты коротко; для больших справок используйте обычные записи лора. При превышении бюджета приложение предупреждает, а не обрезает сохранённый текст.
- Принимается только завершённый блок последнего ответа с подходящими миром, чатом и версией. Запоздалый ответ не затирает ручную правку. Повторно открытый ответ не применяется второй раз.
- Если DeepSeek пропустил блок или нарушил формат, карточки остаются прежними и показывается короткий статус. Новая скрытая генерация не запускается. При ошибке сохранения доступна явная повторная попытка.
- Автообновление не ограничивает общий состав мира числом 40; отдельная сцена по-прежнему до 12 участников, карточка — до шести показателей. До 32 активных действий для модели; число локальных картинок и их общий размер не ограничены DeepRole.
- Кнопка **Экспорт** открывает выбор: **Этот мир** переносит лор, анкеты, портреты и список действий; **Полная резервная копия** дополнительно переносит все миры, настройки, состояния чатов и расстановку портретов. При импорте мира его действия подключаются автоматически, не заменяя настройки других миров. Локальный сейф шифрует эти данные вместе с остальной библиотекой.

Технический блок в ответе сворачивается в короткий статус: сам сюжет и размышления не скрываются. Приложение не может гарантировать, что DeepSeek всегда соблюдёт формат или правильно поймёт события. Любое состояние можно исправить вручную.

## Проверка реализации

Автотесты покрывают парсер, атомарное сохранение, конфликты, изоляцию чатов, резервные копии, сейф, изображения, клавиатуру и RU/EN-интерфейс на узком экране. Сквозной тест загружает production-расширение в отдельный профиль Edge и проверяет настоящий исходящий запрос на макете DeepSeek. В живом аккаунте отдельно проверены создание карточки, ручное сохранение, смена действия и портрета после нейтрального ответа, сохранность после обновления страницы. Проверены браузер Codex и Brave с независимыми библиотеками. Это не гарантия соблюдения формата во всех ответах модели; подробности и ограничения — в ROADMAP.

## English quick start

The character-preparation wand opens a small progress window beside Characters, top-aligned. Drag the heading, use arrow keys on it, or dock it again with the reset icon. Narrow screens keep it within the viewport. Waiting animations respect reduced motion; rotating hints do not claim fake percentages. New preparations request one character at a time, saving each validated profile before asking for the next, until the model reports no people remain, without a fixed total roster cap. Older running two-person jobs remain supported. Scene participants can reference exact keys of already validated people without repeating their profiles; unknown keys, duplicate people and a protagonist listed as a partner are rejected. This works independently of lore names or language, but the model can still overlook people. If the overall JSON is cut short or replaced with a refusal, fully received individual character objects are retained after schema and source-evidence validation, including across service-tab reloads. After an interruption, review and explicitly save prepared profiles, or clean up the temporary chat and continue with the remaining characters. Previous results are reused only when the lore has not changed. Each checkpoint is tied to the exact job, step, chat and reply. No bypass prompt is sent and the server's answer is unchanged. The temporary checkpoint is vault-protected, excluded from exports/backups and cleared when preparation ends or is cancelled.

В новых запусках DeepSeek готовит по одному персонажу за запрос, а расширение сохраняет каждую проверенную анкету до следующего запроса. Подготовка заканчивается, когда модель сообщает, что никого не осталось; общего потолка состава 40 больше нет. Участники сцены могут ссылаться на уже проверенные анкеты из предыдущих запросов. Правила не привязаны к именам или конкретному лору, но модель всё ещё может кого-то пропустить. В проверке видны значения и описания низкого/высокого уровня каждой шкалы; ненужную предложенную шкалу можно убрать до сохранения. Новый промпт требует понятных пояснений без ID записей и названий полей, а оценки способностей не должны выводиться только из возраста, профессии или внешности. Числа остаются предложениями модели, не измерениями. Старые технические пояснения заменяются на экране подсказкой проверить шкалы и цитаты; исходный текст и лор не переписываются. Уже заполненные анкеты и сыгранные значения сохраняют приоритет.

Hide the preparation window with its **×** button or **Escape** while focused inside it. The Characters wand restores it. Hiding survives refresh; it does not cancel preparation or discard its result. If you manually deleted the temporary chat, choose **Chat already deleted** to clear the old cleanup reminder and allow preparation again. This acknowledges your deletion rather than checking DeepSeek's server; it never deletes chats, profiles, portraits or lore. It is available only after preparation finishes or is cancelled. Ready profiles can still be reviewed when temporary-chat deletion fails.

**Open temporary chat** focuses the existing service tab. If it was closed, it opens the saved address of the same conversation in a new browser tab, without sending another prompt or restarting preparation. The address comes from the actual owned chat, preserving its native `/a` route and dropping service-launch markers. Legacy jobs with a valid saved ID use DeepSeek's `/a/chat/s/ID` route. Without a trustworthy ID, the button is disabled with an explanation rather than opening an empty replacement. A conversation already deleted on the server cannot be restored by this button.

The editor has three tabs: **Profile**, **In scene**, **Images**. Switching tabs keeps your draft, and saving keeps the editor open. Add an action directly in Images; the name is saved to this world immediately, while images need Save character. Settings → Characters has a visual list, with a bulk text editor available on demand. The image library is open by default; small uploads are selected for assignment.

All panels below the chat title share a 224 px default width. The width button beside Together and Settings → App → Panels and scene adjust them all between 200 and 360 px. Narrow windows fit automatically without overwriting this preference.

### Ready selfies and AI generation

The **Images** tab explains both methods. Ready uploaded selfies are **not AI image generation**: ask manually with **Ask for a selfie** or in the chat; DeepSeek roleplays agreement/refusal and chooses a collection. A ready photo is shown locally without using an image service. New AI-generated photos require separately enabled image settings and a provider/API key; charges may apply. Suitable ready photos take priority. Relationship boundaries and the character’s right to refuse apply to both methods.

Open **Images → Uploaded selfie collections**. In a category, **Choose from library** lets you select several of this character’s existing images, including assigned action portraits and permanent references. Click **Add selected**, then **Save character**; until saved, changes are a draft. Existing assignments are preserved, duplicates are skipped, and removing a collection photo keeps its source in the library. Already-added photos are marked; **Cancel selection** or Escape closes the picker without saving the selection. The list expands with **Show more**, rather than limiting which library photos can be used. Collections have no application photo-count quota; thresholds and one default collection work as before.

### Protagonist avatar

Mark the character **My protagonist**. DeepSeek receives the hero's name and available portrait keys, and must update the hero from your played speech/actions plus the completed scene. In-character speech may use a configured speaking pose; actions, thoughts, out-of-character requests, past quotes and unsent choices are distinguished from speech. Updates appear after a completed valid reply. Typing alone does not change the avatar. Assign a portrait to the action and keep that key active for this world; otherwise the neutral portrait is used. Personal action restrictions still apply, and the protagonist is never their own interlocutor.

### Shared images and action names

Built-in labels are translated for display: **Happy · happy** always uses the key `happy`. Settings and the model use these exact keys. Custom names may be written in any language, but are not automatically translated or treated as synonyms. `смех` and `laughing` are separate keys. Commas and `/` do not create aliases.

Add each action on its own line in settings. In a character’s **Image library**, select images, choose the main action, open **More actions for these images**, and check additional names. Click **Assign to action**, then **Save character**. Each selected action receives the same images, added to its existing set. This is a shared assignment, not a permanent link: select the same actions again for later additions. Each action has its own variation cycle. DeepSeek still has to choose an allowed action in its response.

Saving keeps the editor open and shows **Saved**. You can add more portraits and save again without resetting the selected action or library. Use **Close** or **Back to characters** separately. Fields you did not edit retain newer scene updates; conflicting edits to the same field are not silently overwritten.

### Upload now, assign actions later

Open a character sheet → **Images → Image library → Upload to library**. Select multiple files at once. They appear under **Unassigned**, so you can organize them later.

Select thumbnails, choose an action below, then click **Assign to action**. Switch to **All** to reuse an already assigned image for another action. Click **Save character** to keep the library, even if you have not assigned any actions yet. Until then, changes are only a draft.

Each character has a separate library. World exports and full backups embed saved image data; no separate photo folder is needed. Images are never sent to DeepSeek. DeepRole has no application quota for collection size, file count or action variations. Removing a variation keeps its image in the library; use the library trash button to delete an unassigned image.

Each upload opens **Compress images?**. **Keep originals** preserves the original file bytes and dimensions; **High quality** uses the long edge in **Settings → Appearance → Uploaded image quality** (1920 px by default, adjustable from 256 to 4096); **Save space** uses WebP quality 82% and a long edge up to 1280 px, respecting any lower configured edge. High quality preserves fitting originals and resizes larger files at WebP quality 92%. Small sources are never enlarged. Cancel adds nothing. There is no per-image encoded-size quota. Existing images stay unchanged: re-upload originals for more detail. This applies to portraits, library pictures, uploaded references and selfies, not provider result resolution.

Use the library’s **Preview size** slider (96–280 px) to inspect faces; its preference is remembered independently of the character draft. The separate **Reference preview size** slider changes neutral and alternative thumbnails and their picker grid. It is remembered across openings without changing source images, reference selection or library tile size. **View** opens the full image without altering selection. The viewer supports wheel and +/− zoom up to 128×, drag-to-pan, a fixed fit minimum, 100% and fit buttons, and 0 / F / Escape shortcuts. Zoom does not create extra image detail.

Context, character, world and control panels keep at least a 1 px gap, including their hover controls. The controls sit beside each panel rather than in a separate row between cards. Dragging finds the nearest free space; old overlaps, restored panels and viewport changes are handled too. On very small screens they use a scrollable column until there is enough space for free positioning. Floating character portraits remain independent.

You can select **My protagonist** and upload action portraits before pressing **Save character** once. If a scene update arrives while editing, portraits still save and fields you left untouched keep their latest values. Competing changes to the same field or the same action’s image set show a warning; unsaved edits remain in the open form.

### Multiple images per action

In a character sheet, choose **Portrait action → Add images**, select one or several PNG/JPG/WebP files, then **Save character**. There is no application image-count quota. Thumbnails preview variations without changing the action; each trash button removes just that image. Uploading again adds to the set instead of replacing it.

Each accepted scene update advances a shuffled cycle without repeating an image until all have been used. A new round avoids repeating the last image immediately. Each action has its own cycle; missing action images use the neutral set. Opening the gallery, dragging, refreshing and rereading the same reply do not advance it. The saved cycle follows this lore’s shared game across continuation chats; the original profile is unchanged. World exports and full backups include every image; full backups also include the current game’s cycle. Older single-image files still work.

### Panel controls and automatic states

**Adaptive sizing** is enabled by default. Toggle the framing icon beside the group controls, or use **Settings → App → Adaptive sizing**. Portraits and options share the available space with the floating panels. In a constrained window, portraits become a compact, horizontally scrollable row; panel icons open one panel at a time (Escape closes it). Enlarging the window restores the full layout. Saved portrait sizes and panel minimization choices are not overwritten. Manual portrait movement remains available in the full layout; the compact row follows the automatic arrangement.

Drag a portrait's lower-right corner to resize it up to the visible page height. Its 3:4 image, captions and controls fit on screen; the old 360 px cap is gone. Explicitly resizing makes just that card independent of automatic grouping and pinning, so repeated updates and refresh cannot shrink it back. Narrow windows temporarily fit it without rewriting the saved size or hiding it in the compact row. Drag its name to move it; snapping places it beside the choices without shrinking it. **Reset layout** returns it to the automatic group. Arrow keys resize too; Shift uses larger steps and Escape cancels an active drag. Layout changes do not modify scenes or send model requests.

Drag the context, memory, characters, reply-choice or world panel itself to move it; there is no separate handle on each panel. A short click on a control inside still performs its normal action. The **−** button appears on its panel’s hover, and stays available on touch devices. The top group handle is always visible. Enable **Together** to drag the whole group from any panel, or disable it for independent movement. Focus a panel and use the arrow keys for keyboard movement. Minimized panels snap into one row of icons; select an icon to restore it. The reset arrow restores the default layout and expands all panels. Layout is saved in this browser and does not affect lore or tokens. Portrait drag and resize handles appear on hover or keyboard focus; touch devices keep them available.

Mood, condition, current goal, relationships and stats already update automatically when DeepSeek includes valid changes in its completed reply. Missing or invalid updates leave previous values unchanged. These are the model's interpretation of the scene, not independently measured scores. Shared profile fields are not overwritten. Save manual edits to include them in the next message.

**Export** now opens one dialog: **This world** includes lore, profiles, portraits and the world's action list; **Full backup** includes every world, settings and saved chat states. Imported world actions are available automatically without replacing other worlds' settings. In **Settings → Characters**, changes apply to the connected world; with no world selected, they change the shared fallback list. Older world files remain compatible.

Sheets are enabled by default. Connect a world and continue chatting, or use **+** to create a sheet yourself. If previously disabled, enable **Settings → Characters → Character sheets**. **In scene** shows your protagonist and current participants; **All** has the complete roster and name/alias search. The compact list below the context indicators contains names, roles and actions, not images. Select a name to edit. The expand button beside **+** opens a centered portrait gallery of every character; use the pencil to edit within the same window. Saving keeps the editor open. Use Back to characters to return to the gallery without clearing its search. If participants aren’t known yet, everyone is shown with a short note. Filters affect the display only and reset when you switch chats or worlds. Mark **My protagonist** for the left floating portrait; the current interlocutor starts on the right.

**In the scene** means physically present; their portrait stays visible even when they talk to someone else. **Talking to the protagonist** can be checked for several people at once. Save the sheet to apply the selection to this chat. Speakers appear together at equal size to the right of the choices when space allows; quieter bystanders are about 15% smaller, with 6 px between portraits and aligned lower edges. Changing the speaker changes the leading portrait. Tight viewports reflow the group rather than covering the choices; manually placed portraits keep their own positions and sizes. Unchecking one speaker leaves the others unchanged and does not make them leave. The protagonist cannot be their own speaker. The next completed reply may change the list. Reopening an already consumed reply does not undo your edit.

All scene participants have separate floating portraits, outside the reply options’ background. Portraits stay visible in their current positions while DeepSeek generates the next reply; their states update after the reply. The small eye button beside the panel controls hides or shows all floating portraits without deleting any images or positions. The same setting remains under **Settings → Characters**. The default gap from the choices is 24 px where side placement fits. Drag the **name handle** anywhere on screen, including outside the chat column; resize from the **lower-right corner**, or select the **image** to open the sheet. Images stay 3:4. Moving portraits never creates a gap between the reply and its options. Positions and sizes are saved separately for each chat and world; moving them never changes memory or sends a request. Saved positions stay pinned while scrolling and fit inside a resized viewport. **Reset layout** restores the current chat; **Settings → Characters** offers an all-chat reset. Arrow keys move the focused handle or resize the focused corner; Shift gives larger steps, Esc cancels dragging. Legacy layouts remain readable; the next move stores a viewport position.

The portrait editor starts on the current action. **Portrait action** previews an image without changing the character’s action or requiring a save. Change the actual action under **Now in this game**. A missing or unreadable image falls back to the default portrait, then a silhouette; stored images are not deleted.

Profiles and automatically updated states belong to the lore’s shared game. Only its current chat writes progress; other chats can resume from the latest state. Existing profiles are not overwritten by model replies. The first two filled stats appear below the portraits, in sheet order; open a portrait to see or edit all six. Unknown values stay empty. Full backups include states and images; world exports contain the current effective roster and exclude played game state. See ROADMAP for automated and live-account verification status.
# Диагностика подготовки / Preparation diagnostics

UX266: служебный журнал находится за **Для технической поддержки → Открыть технические данные**. Успешная подготовка, текущая остановка и дальнейшее действие видны без открытия технических данных. Общая диагностика: **Настройки → Расширенные настройки → Инструменты технической поддержки → Диагностика**.

UX266: open **For technical support → Open technical data** to inspect the report. Preparation success, a current failure and the next action remain visible without opening it. General checks are under **Settings → Advanced settings → Technical support tools → Diagnostics**.

В окне подготовки раздел «История проверки ответов» сохраняет последние 24 события, включая предыдущие попытки: ID, шаг, этап проверки, время, код, длину ответа, число готовых анкет и конкретные пути ошибочных полей с требованиями и типом/длиной значения. Исправленные ошибки отмечены «Исправлено — подготовка продолжилась», текущая остановка и исправление в процессе показаны отдельно. Готовая подготовка сопровождается пояснением, что дальше нужно проверить и сохранить предложения. «Скопировать диагностику» готовит отчёт для разбора; если буфер недоступен, появляется поле для ручного копирования. История доступна после удаления чата и сохранения анкет. Полный ответ, лор и API-ключи не включаются; раскрытие и копирование не отправляют запрос.

При неправильном формате расширение один раз на партию просит исправленный JSON с конкретными ошибками. Повторная ошибка останавливает подготовку; готовые анкеты сохраняются. Оборванный ответ требует ручного продолжения; отказ модели не обходится. В служебном чате DeepThink включается только при однозначно распознанном переключателе с проверяемым состоянием; изменение восстанавливается при очистке. В отчёте видно, подтверждён ли режим. DeepThink не гарантирует правильную структуру, проверки не ослабляются.

“Reply validation history” retains the latest 24 events after chat deletion and profile saving: request ID, step, validation stage, time, code, reply length, prepared count and specific field paths with requirements and value type/length. Resolved failures, corrections in progress, current terminal errors and earlier attempts have distinct labels. Completed preparation explains that proposals still need review and saving. “Copy diagnostics” exports a safe report, with a manual-copy fallback. Full replies, lore and API keys are excluded; viewing/copying sends no request. One automatic JSON correction per batch receives the specific errors; a second failure stops preparation without losing prepared profiles. Interrupted replies require manual continuation; refusals are not bypassed. DeepThink is enabled only for an unambiguous, verifiable control in the service chat and the extension's change is restored during cleanup. The report records whether the mode was verified; it cannot guarantee valid output and validation remains strict.
