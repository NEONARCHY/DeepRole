# RP386 — следующий ход после переноса

Ожидания закреплены 17 ноября 2026 **до первого запуска**. Только вымышленные
данные, изолированный Edge и синтетические ответы; живой аккаунт не используется.

Матрица RU/Fetch и EN/XHR, по шесть случаев:
- восстановление первой пары после reload, automatic/review;
- обычное завершение первой пары без ухода, automatic/review;
- внеигровая реплика в скобках, после отправки настройка выключена;
- игровая реплика в скобках, после отправки настройка включена.

1. Старый чат недоступен. Перенос начинается с сохранённой памяти, без POST
   в старый чат. Первый ответ и исходная реплика записываются ровно один раз.
2. Игровой ответ содержит два предложения: факт о жетоне в медной коробке
   и условное обещание о фонаре. Automatic сохраняет только факт, review
   оставляет оба на проверке. Внеигровой ответ не создаёт фактов/предложений.
3. Назначение первой реплики фиксируется при отправке. Переключение настройки
   скобок во время ожидания не превращает обсуждение в сыгранное событие
   и не отменяет уже отправленное игровое действие.
4. Следующий обычный ход получает инструкцию памяти и, если первый факт
   сохранён, его точный текст в подключённой памяти. Нет повторного переноса,
   запроса в старый чат или автоматического повтора модельного запроса.
5. Второй ответ добавляет новый факт о печати в зелёном ящике. Automatic
   сохраняет его; review оставляет на проверке. Прежние ID очереди сохранены.
6. После повторного чтения и reload ровно четыре ревизии, две пользовательские
   исходные реплики без подмешанного контекста, прежние ID фактов/очереди.
   Всего два явных POST пользователя; новая реплика в редакторе не заменяется.

Первый прогон — на RP385; найденные пропуски исправляются без изменения
этих ожиданий, затем повторяются этот набор и прежние сценарии.

## Контроль после первого исправления

До запуска двух дополнительных сценариев закреплено: обычный ответ завершён,
но чтение истории временно возвращает 503. До ручной проверки не переключать
игру и не записывать сцену. После появления истории «Проверить ответ DeepSeek»
завершает перенос и сохраняет первую пару; следующий ход проходит по пунктам
4–6 выше. Ровно два POST, никакой автоматической повторной отправки. RU/Fetch
и EN/XHR; это дополнение к исходным 12 случаям, а не замена их ожиданий.

## Результат на RP385 и исправление

На исходной сборке 4/12 сценария прошли: следующий ход после восстановления
уже использует новый факт и сохраняет очередь проверки. Восемь отказов:
четыре обычных переноса теряют первую пару, ещё четыре восстановления меняют
назначение первой реплики вслед за настройкой скобок.

Первоначальный стенд ставил форму отправки под виджетом DeepRole; второй клик
перехватывался виджетом. Форму поставили в область переписки, затем полностью
повторили отрицательный прогон на RP385 (`test-results-rp386-baseline-fixed-fixture`).
Принудительный клик и ослабление проверок не применялись. Два модульных
контроля отдельно воспроизвели смену назначения реплики в обоих направлениях.

При обычном завершении потока первая отправка с включённой записью теперь
сохраняет доказательство попытки и использует ту же атомарную запись через
проверку серверной истории, что восстановление после reload. Нельзя считать
завершение потока доказательством записи сцены. Пока история недоступна,
доступна ручная проверка без повторного POST; неполный/чужой ответ не принимается.

`ContinuationDraft.purpose` фиксируется при отправке и входит в guard попытки.
Версия режима записи фиксируется и для внеигровой реплики, но автоматические
изменения дополнительно требуют исходной инструкции памяти; сама внеигровая
пара не создаёт игровых фактов. Старые черновики без purpose остаются допустимыми.
В тестах отсутствие необязательной очереди нормализовано как пустая очередь.

## Итоговая проверка

- Новый набор: **14/14** (1.2 минуты), `test-results-rp386-final`.
- Прежний набор: 91/92 (5.7 минуты), `test-results-rp386-regression`.
  Единственный отказ — обычный первый ход RU не получил инструкцию памяти
  во время параллельного запуска нескольких наборов. Без других прогонов
  точный сценарий прошёл за 6.9 секунды без изменений кода и ожиданий:
  `test-results-rp386-first-turn-recheck`. Всего подтверждены **106 разных
  браузерных сценариев**, один потребовал повторного запуска. Это не единый
  безошибочный прогон; чувствительность первого хода к нагрузке сохраняется
  как ограничение проверки и должна учитываться при живом повторе.
- Модульные: 404/405 в 18 файлах на Node 24.22.1. Сценарий 100 порций истории
  дважды достиг 30-секундного лимита при параллельной браузерной проверке.
  После её завершения тот же сценарий прошёл отдельно за 14.9 секунды;
  таймаут и ожидания не менялись. Все **405 разных проверок** подтверждены
  с этим точечным повтором. Не запускать этот нагрузочный тест одновременно
  с несколькими браузерными наборами на данной машине.
- TypeScript и `git diff --check` прошли. Новые тесты purpose отдельно
  отвергают неверные значения и сохраняют совместимость прежних черновиков.

Все браузерные ответы синтетические. Живой аккаунт и фактическая перезагрузка
установленного расширения этим прогоном не подтверждаются. Следующий этап —
повторный перенос из продолженного чата в третий при недоступном втором.
