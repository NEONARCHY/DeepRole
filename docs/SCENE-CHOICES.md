# Сценические выборы DeepRole

## Уже работает

Режим действует только в чате с подключённым миром. DeepRole просит DeepSeek закончить каждую ролевую сцену, включая короткий диалог, четырьмя вариантами. У каждого варианта есть короткая подпись и текст следующей реплики или действия героя. После завершения ответа служебный блок заменяется кнопками под сценой. Если сайт перерисовал ответ или пользователь вернулся в чат, DeepRole повторно находит сохранённый блок и восстанавливает карточку **без нового запроса**. Кнопки показываются только для последнего ответа: старые варианты не переносятся под новую сцену.

Если вариантов нет, под последним распознанным ответом DeepSeek появляется **«Предложить варианты»**. Короткое пояснение рядом сразу сообщает, что кнопка отправит отдельный видимый запрос в чат. DeepSeek получает просьбу дать четыре хода для уже написанной сцены, не продолжать её и не обновлять память. Новый ответ остаётся в истории DeepSeek; пользователь сам выбирает ход. Модель может не выполнить формат — тогда лор не меняется, а повторный запрос запускается только явно.

| Вариант | Драматическая роль |
| --- | --- |
| Доброжелательный | Помочь, сблизиться, проявить доверие или заботу. |
| Нейтральный | Выждать, уточнить, поставить практическую цель. |
| Жёсткий | Возразить, надавить, рискнуть отношениями или сыграть эгоистично. |
| Неожиданный | Предложить иной ход, который всё ещё вытекает из сцены. |

Нажатие заполняет пустой черновик. Пока вставленный текст не изменён, можно нажать другой вариант. Собственный или уже отредактированный черновик не перезаписывается. Пользователь редактирует и отправляет его самостоятельно. Кнопка не решает исход за персонажей, не отправляет сообщение и не сохраняет запись в память. Переключатель рядом с индикатором контекста действует для всех чатов с миром; настройка входит в резервную копию.

## Правила последствий

Тон выбора не равен результату. Доброта не гарантирует роста симпатии; жёсткость не обязана закрывать путь к цели. Персонаж реагирует по своему характеру, привычкам, интересам, текущей сцене и установленным фактам. Например, жёсткость может повысить уважение и одновременно снизить доверие. Неожиданный ход должен быть правдоподобным, а не случайным событием без связи с сюжетом.

Сейчас последствия живут в переписке DeepSeek. В долговременный лор они попадают только через подтверждаемое «Обновить лор» или ручную запись. Предложенные варианты не считаются произошедшими событиями до отправки выбранной реплики.

## Следующий слой: состояние отношений

Для каждого персонажа полезно хранить несколько независимых граней — **доверие, близость, уважение, страх и совпадение целей** — вместе с текстовыми причинами изменений. Их нельзя вычислять только по номеру кнопки. Обновление должно опираться на реально отправленный выбор и последовавшую сцену; пользователь подтверждает или исправляет его перед сохранением. Числа, если появятся, будут обзором изменений, а не скрытым правилом поведения модели.

Персонажам нужны собственные предпочтения и границы, записанные в лоре. Они объясняют, почему один и тот же выбор действует на разных героев по-разному. Важные конфликты должны оставаться в виде конкретных фактов («обещание нарушено», «согласился помочь»), чтобы продолжение в новом чате не свелось к голому числу.

## Следующий слой: маршруты и флаги сюжета

Разделить **канон мира** и **состояние текущей истории**. Канон содержит устойчивые правила и биографии. Состояние истории хранит открытые цели, обещания, секреты и последствия уже сделанных выборов. В новом чате пользователь решает, какую ветку продолжить; неподтверждённые возможности не превращаются в события.

Для полноценного сценарного режима нужны журнал принятых решений, просмотр изменившихся отношений, явные флаги сцен и перенос состояния вместе с пересказом истории. Каждый пункт должен позволять исправить ошибочную интерпретацию модели без переписывания исходного лора.

## Ограничения и восстановление

DeepSeek может пропустить или исказить служебный формат. Кнопки показываются только для полного корректного набора из четырёх вариантов; сюжетный текст при ошибке остаётся доступным. Источником восстановления служит загруженная история чата, а не отдельная незашифрованная копия сюжета. Если сайт ещё не загрузил последний ответ или его разметка не распознана, DeepRole не угадывает, к какой реплике прикрепить варианты.

Запрос не запускается при занятом поле ввода, продолжающемся ответе, другом незавершённом запросе, закрытом сейфе или смене чата/сцены во время подготовки. Двойной клик не отправляет два запроса. Ошибка DeepSeek или сети освобождает ожидание и позволяет явную повторную попытку, без автоматической отправки. В служебных метаданных сохраняется только идентификатор сцены, не её текст; записи, предложения памяти и слепки из вариантов не создаются.

Автоматические проверки охватывают восстановление истории и перерисовку, RU/EN, 360/1280 px, явный запрос, защиту черновика, смену сцены/чата во время подготовки, ошибки и отсутствие записи в лор. Production Chrome MV3 проверяется в отдельном headless-профиле на макете; общий адаптер — в Chromium и Firefox. Это не заменяет проверку на настоящем аккаунте DeepSeek. Изменение DOM сайта всё ещё может потребовать обновления адаптера.
