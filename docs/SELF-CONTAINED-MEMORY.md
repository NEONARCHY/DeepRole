# Меньше повторяющихся данных в запросе

## Что сделано в третьем пункте

Добавлен ещё один обратимый формат передачи игровой памяти: названия полей пишутся один раз, затем идут строки значений. Часто используемые поля расположены первыми; отсутствующие значения в конце строки не повторяются. Все выбранные тексты, цитаты, отрицания, условия, статусы, исторические персонажи и источники остаются в текущем запросе.

Расширение сравнивает этот формат с прежним сжатием, включая полную инструкцию чтения и размер всего добавляемого запроса. Таблица используется только при уменьшении и символов, и локальной оценки токенов. Для небольших или неудобных наборов остаётся прежний формат. Подбор по полному бюджету может вместить больше целых записей; записи ради сжатия не обрезаются.

Включать настройку не нужно. Дополнительных запросов модели, нового формата хранения или изменений исходного лора нет.

## Почему это не «отправить один раз, дальше только изменения»

Текущий DeepSeek web-запрос содержит новый prompt и ID родителя. Полученная история и квитанция HTTP говорят о сохранённом чате и доставке запроса, но не описывают фактическое окно, переданное модели. Нельзя доказать, что ранее отправленный фрагмент сохранился в нём после накопления истории, переключения ответа или ограничения контекста.

Поэтому **полноценная межходовая дельта пока не реализована**. Удалять из нового запроса факт только потому, что он уже отправлялся, нельзя считать безопасным. Эта итерация уменьшает повторение служебных полей внутри самодостаточной памяти каждого хода. Дословные неизменённые факты всё ещё могут повторяться между ходами.

Для настоящего режима «только изменения» нужен подтверждённый контракт окна/закреплённой основы со стороны провайдера и механизм её восстановления. Это остаётся отдельным открытым ограничением RP-05. Результат этой итерации не выдаётся за очистку или сжатие нативной истории DeepSeek.

## Сбои и продолжение

Каждый запрос содержит собственное описание таблицы и все используемые ею данные. Ссылки разрешаются только среди строк этого запроса. Старые запросы, квитанции, порядок карточек и другая вкладка не служат словарём.

После отказа отправки, ручного повтора, перезагрузки, изменения/сброса данных или перехода в новый чат память собирается из актуального состояния. Подтверждение доставки и механизм продолжения не менялись. Таблица не является форматом новых фактов: входящие предложения по-прежнему проходят прежнюю строгую проверку.

## Что измерено

На128 **прежних, уже известных** синтетических сценариях при одинаковом выбранном содержимом:839113→827945 символов полных запросов,210331→207539 по локальной оценке токенов. Дополнительная экономия около1,3%;102 запроса выбрали таблицу,26 сохранили прежний формат. Это механическое сравнение кодирования с бюджетом20000, не независимая проверка качества, скорости или реальных токенов DeepSeek. [Отчёт](benchmarks/rp279b-wire-results.json).

Первый плотный вариант давал лишь4 таблицы/128 и252 символа экономии; отчёт сохранён. Разрежённые строки улучшили результат без изменения источников. Сравнение JSON-хешей было заменено строгим структурным сравнением: порядок ключей объекта не является изменением данных. Unit проверяет обратимость каждого варианта, опасные строки, пустые поля, недопустимые ссылки и полный бюджет. Итоговые native/typecheck/package проверки — начало [CODEX-HANDOFF](../CODEX-HANDOFF.md).

Следующий согласованный prompt пользователя относится к **пункту4: новому независимому набору длинных историй**. Уже виденные сценарии этой итерации для него не подходят. RP-05 целиком остаётся открыт; чтение нового формата живой моделью здесь не проверено.

Финальные проверки:796 выбранных модульных тестов и16 браузерных сценариев на русском/английском прошли; TypeScript и проверка пробелов успешны. Браузерные ответы синтетические: проверены фактический исходящий формат, полные источники,503 и ручной повтор, перезагрузка и переход в новый чат. Chrome/Firefox и три архива пересобраны и сверены; это не обновляет установленную копию автоматически.
