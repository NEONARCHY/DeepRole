# RP307 — лимит промпта выбранной модели Venice

## Источник ограничений

Venice указывает модельный лимит описания в
`model_spec.constraints.promptCharacterLimit` каталога
[`GET /models`](https://docs.venice.ai/api-reference/endpoint/models/list).
Это прямо описано в [Image Generate](https://docs.venice.ai/api-reference/endpoint/image/generate).
Общий пример ограничения в схеме endpoint не заменяет значение конкретной модели.

DeepRole уже получает каталоги `type=image` и `type=inpaint` при подготовке и перед
отправкой. Числовые лимиты применяются ко всем выбранным ID, включая новые модели;
ручного списка названий/догадок по названию нет. Генерация и редактирование имеют
раздельные ограничения, даже если каталоги используют один ID. Если один режим
не сообщил лимит, ограничение другого режима ему больше не приписывается.

Без модельного числа ограничение остаётся неизвестным. Сохраняется существующая
локальная защита12 000символов; это не обещание, что провайдер принимает столько.
Лимиты выше12 000 пока также ограничены локальным форматом запроса. Число считается
по UTF-16 длине строки JavaScript; для emoji это консервативнее числа кодовых точек.

## Что изменено

Числовая подсказка DeepSeek существовала раньше, но не давала размер неизменяемой
части. Итог складывается из сцены, стиля, полных описаний персонажей, действий,
расположения и пояснений к референсам. Короткая сцена сама по себе не гарантирует,
что всё это поместится, например, в1500символов.

Теперь первичная подготовка и изменение референсов передают `promptComposition`:

- ID выбранной generate/edit модели;
- размер стиля и оформления кадра;
- размер общего указания для группового кадра;
- затраты на каждого персонажа: без картинки либо с обычным/альтернативным референсом;
- запас на подписи полей, разделители и безопасный остаток.

Размеры рассчитываются теми же функциями, что собирают компактный окончательный
промпт. Учитываются полные canonical/appearance, а не только сокращённый фрагмент
в roster. В новые метаданные попадают ID и числа, не API-ключи/картинки/копии анкет.

DeepSeek получает правило: сначала определить фактических участников и прикрепляемые
референсы, затем вычесть их расходы из лимита и распределить остаток между сценой
и ВСЕМИ генерируемыми описаниями. Отсутствующие персонажи из таблицы не учитываются.
Прикреплён хотя бы1референс — edit; нет прикреплённых картинок — generate. Обычный
референс всё равно может прикрепляться автоматически при legacy `reference:none`;
учитываются политика/override/referenceBudget и наличие назначенных картинок.

Это подсказка модели, а не доказательство соблюдения длины. Существующий preflight
проверяет полный реально собранный текст до платного generate/edit запроса.
Сохранённые анкеты, стиль, идентичности, состав кадра и картинки не обрезаются.
Если они уже превышают лимит, нужно выбрать более вместительную модель либо самому
сократить описание для изображений/стиль. Автоматического платного retry нет.

«Создать иллюстрацию» подготавливает новый план с текущими настройками.
«Попробовать ещё раз» сохраняет прежний запрос/модель/параметры, как и раньше.
Селфи сохраняют собственную сборку9:16 и существующий provider preflight;
эта итерация не переводит их на новый план иллюстрации16:9.

## Проверки и границы

87модульных проверок прошли: новые/общие ID, неизвестные/невалидные числа,
генерация/edit, emoji, полные длинные анкеты,0/1/2/40участников, неизменность исходных
данных, точная граница, защита до provider call и frozen repeat. Проверка75произвольных
модельных ID — синтетическая проверка отсутствия whitelist, не live перечень Venice.

Первые2native prompt-budget теста RU/EN прошли: подготовленная служебная подсказка
содержит обе модели, ограничения и measured composition; референсы передаются edit,
черновик сохраняется. Ответы DeepSeek и Venice в этих тестах подставлены.

В первом расширенном прогоне8старых UI assertions не учитывали вложенные раскрытия
SupportDetails.2старых reference-review fixtures ожидали ответ в основном чате,
а приложение работает через отдельный временный чат; оба воспроизвелись и на
предыдущем RP306 Chrome ZIP. Тестовые fixtures приведены к нынешнему workflow,
не runtime ради прохождения теста. Первый результат сохраняется отдельно.
После появления корректного review старое сравнение dataURL с photo-store address
также актуализировано: тест гидратирует Blob.text() как PhotoAssets.read и сравнивает
все исходные поля и точные исходные data URL, а не исключает картинки из проверки.

Финальный E2E:12pass/4skip/0fail/0flaky, RU/EN,320/900px.8UI проверок Chromium/Firefox
и4native Edge MV3 (initial budget + reference review).4Firefox skips относятся только
к Edge MV3. Проверяются cleanup временных чатов, отсутствие служебных сообщений в
основном чате, review после reload, разные references, exact frozen retry и cancel.
Chrome/Firefox и три ZIP пересобраны; финальные bytes/CRC/SHA checks выполняются
после упаковки. Источник QA требует Git checkout, source ZIP исключает tests/private-assets.

Личный лор и установленная пользовательская копия не менялись. Платные Venice
генерации и живые ответы DeepSeek этой итерацией не проверялись. Запросы каталога
из пользовательского аккаунта не выдаются за выполненную сверку всех реальных ID.
