# RP385 — первый ответ после восстановления переноса

Ожидания закреплены 17 ноября 2026 до первого запуска новой проверки.
Используются только вымышленные сцены, изолированный Edge и ответы стенда.

Матрица: RU/Fetch и EN/XHR, по три случая: автоматическая память,
режим с подтверждением, неполный ответ с последующей ручной проверкой.

1. Исходная игра/лор сохранены. Первый POST нового чата содержит инструкцию
   действующего режима памяти. До полного ответа перенос не применяется.
2. После перезагрузки точная завершённая серверная пара подтверждает перенос
   без нового POST. Исходная пользовательская реплика записывается без
   подмешанной памяти; ответ записывается целиком один раз.
3. В автоматическом режиме сыгранный обычный факт попадает в память один раз,
   условное намерение остаётся на проверке. В режиме с подтверждением оба
   предложения ожидают пользователя, автоматически ничего не утверждается.
4. Частичная пара не создаёт записанную сцену/память/новую привязку. После
   её завершения ручная проверка применяет те же правила, не отправляет POST.
5. Повторное обновление и чтение истории сохраняют ID записей, фактов и
   очереди; не создают дублей и не изменяют новый текст в редакторе.

Первый прогон проверяет RP384. При пропусках — исправление с отдельным
повтором этого набора и прежней цепочки; исходные ожидания не ослаблять.

## Найдено и исправлено

На RP384 все шесть сценариев остановились на отсутствии инструкции памяти
в первой отправке (`test-results-rp385-baseline`). Перед этим исправлена
ошибка самого стенда: значение режима `auto` заменено на контрактное
`automatic`; повтор на исходной сборке дал те же шесть пропусков. Ожидаемые
результаты не менялись.

В первую отправку добавлена инструкция действующего режима. До отправки
сохраняются его версия и ограничения полей анкет. Восстановление через историю
повторно проверяется в background по сохранённому хешу. Под одним guard
вкладки/попытки и одной транзакцией базы переключается игра, создаётся журнал
первой пары и применяется обычный механизм сопровождения игры. Неполный ответ
не создаёт запись. Ошибка записи откатывает всю операцию; доказательство
попытки остаётся для повторного GET без нового запроса модели.

Дополнительный тест обычного повторного чтения истории выявил две ошибки
в режимах automatic/review: исходная реплика без контекста считалась другой
версией серверного сообщения. Для первой пользовательской записи сохранено
точное исходное тело отправки в `continuationNativeContent`. Это поле нужно
только для распознавания той же записи в той же ветке по ID и точному тексту;
оно не является разрешением автопамяти или генерации изображений. Полный
текст находится в библиотеке истории с обычным шифрованием при включённой
защите, а не в session или интерфейсе пользовательской реплики. Изменённое
тело не получает прежние подтверждения. Старые записи без поля допустимы.

Проверены откат при ошибке базы и смене страницы, отмена/новый токен/чужая
вкладка, сериализация, запрет неверной роли/родителя/суффикса, выключение или
смена режима во время ожидания, старый черновик без разрешения автопамяти.

## Итоговая проверка

- 402/402 модульных теста, 18 файлов, Node 24.22.1; TypeScript и diff-check прошли.
- 84/84 сценария цепочки переноса, включая шесть новых, 5.7 минуты:
  `test-results-rp385-regression`.
- 8/8 сценариев обычного первого хода, 55.9 секунды:
  `test-results-rp385-first-turn`.
- Синтетические страницы и ответы в изолированных профилях Edge. Живой
  DeepSeek, лимиты аккаунта и установленная копия этим прогоном не проверены.
- Chrome/Firefox и ZIP собраны, по 23 файла проверены побайтово. Тестовая
  установленная папка обновлена с резервной копией; открытый Edge может
  продолжать использовать прежний код до перезагрузки расширения.

Продолжение: следующий обычный ход после восстановленной пары; первая пара
переноса без ухода со страницы. Предстоящий независимый прогон должен проверить
контекст новой памяти, сохранение очереди спорных предложений и отсутствие дублей.
