# Подбор памяти по теме вопроса

DeepRole учитывает конкретные слова темы во всём тексте принятого факта и полном названии задачи. Это помогает найти давнее сведение или завершённое дело, даже если важное слово находится далеко от начала записи. Всё происходит при обычной отправке сообщения, без новой кнопки или обращения к модели.

Например, дело называлось «Передать телеметрию после разрешения диспетчера», а позднее было записано кратко: «Поручение выполнено». Вопрос про телеметрию теперь получает дополнительное совпадение с полным названием этого завершённого дела. Условие, точная исходная реплика и статус выполнения передаются как раньше. Новые разговоры, в которых лишь повторяется имя персонажа, не получают этот тематический бонус.

## Как выбирается тема

Дополнительный приоритет использует прежнее приведение слов к поисковой форме. Из него исключаются известные имена и псевдонимы персонажей, обычные слова вопроса вроде «напомни» и распознанные формы действий, для которых уже есть отдельный поиск перефразирований. Эти слова не удаляются из запроса или памяти.

Слова, встречающиеся почти в каждой записи, имеют меньший вес относительно редкой конкретной темы. Приоритет ограничен; повторение одного слова много раз не увеличивает его. Частоты пересчитываются только по текущим принятым актуальным фактам. Временный кэш хранит слова текста и названия задачи, но не выбранную историю, владельцев или статус дела; правки текста, названия и состава имён обновляют его.

Этот новый приоритет не ищет тему в длинной исходной цитате, внутренних ключах, ID или значениях сравнения состояний. Цитата остаётся доказательством, а не набором тегов для всех фактов из одной сцены. При явном вопросе «Что Нора обещала Мире?» сохраняется прежний приоритет проверенных исторических владельцев — новый бонус к нему не добавляется.

## Смысл и ограничения

Мнение не становится установленным фактом, обещание — выполнением, а давняя позиция — нынешней. Полные цитаты, условия, отрицания, исторические ID и временные отметки не меняются. Неясное имя или местоимение не получает выдуманного владельца. Поиск видит лишь текущий переданный набор памяти своего мира; старые исключённые варианты или другая игра не возвращаются через кэш.

Это ограниченный локальный поиск по словам, не универсальный семантический поиск. Незнакомое перефразирование без общих слов может не сработать. Собственное окно DeepSeek и серверная переписка не сокращаются этим изменением.

## Когда посторонние записи не отправляются

При явном вопросе вроде «Что известно о кислороде?» DeepRole может отправить только записи с совпадением по теме, не добавляя ещё семь разговоров о погоде ради заполнения места. Для этого каждое оставшееся содержательное слово вопроса должно находиться в полном тексте или названии задачи, хотя бы одно — отличать записи друг от друга. Все слова темы должны быть покрыты целыми записями, которые действительно поместились в общий бюджет. Иначе используется прежний подбор; частичная цитата не создаётся.

Открытые дела, имеющие даже общее слово темы, тоже остаются кандидатами: вопрос о ключе от часов не исключает незавершённый ремонт часов. Лишь имя персонажа не считается темой. Другие сохранённые дела и сведения не удаляются из библиотеки; меняется только подбор для этого запроса. Обязательный вручную закреплённый лор остаётся.

Повествование без распознанного начала вопроса, неизвестная часть темы, неясное имя/местоимение, явный вопрос о владельце и запрос с распознанным действием оставляют прежний тематический подбор. Для короткого «продолжай» есть [отдельный ограниченный набор напоминаний](CONTINUATION-MEMORY.md), а не отсечение всего хвоста. Это не означает, что вся недавняя память или каждое открытое дело всегда помещается в запрос.

## Проверка качества

Фиксированный RU/EN набор содержит 48 примеров с шестью тематическими словарями: мастерская, фэнтези, космос, расследование, домашняя история и выживание. Четыре ситуации проверяют позднее важное слово в тексте, предмет длинного названия завершённого дела, давнюю тайну и владельца условного обещания. Это синтетические примеры двух найденных проблем, не оценка всех возможных лоров.

| Что измеряется | Прежний подбор | Новый подбор |
| --- | ---: | ---: |
| Правильная первая запись | 24 из 48 | 48 из 48 |
| Нужные факты действительно вошли в запрос | 24 из 48 | 48 из 48 |

Во всех показанных целевых записях проверяются полный источник, условие, вид и статус. Дополнительные проверки покрывают имена и пересечения имён, неясных владельцев, цитаты/ключи без тематического текста, полные названия, частоты, правки и 2000 новых отвлекающих записей. В установленном Edge синтетическая история проходит четыре настоящих захвата XHR с открытием и выполнением дела и двадцатью новыми записями; последующие POST и перезагрузка сохраняют правильные старые сведения. Живое поведение модели проверяется отдельно.

Отдельный фиксированный набор ограничения хвоста содержит 24 целевых и 24 защитных RU/EN примера с четырьмя тематическими словарями. Целевые запросы выбирают 32 нужные записи вместо192; все24 содержат заданные нужные факты, прежде20/24. Для20 случаев, где прежний запрос уже содержал все нужные факты, суммарная полная добавка уменьшается с77450 до56353 символов (27,2%). Четыре составных случая также исправляют пропуск второго предмета; они не используются для сравнения размера одинаковой нужной памяти. Все24 защитных случая совпадают с прежним результатом. Эти числа относятся к синтетическому набору, не к native tokenizer или всем возможным сообщениям.

## English

Story-memory retrieval now adds a bounded topic score using the complete accepted fact text and full task title. Known character names, question framing and recognized actions do not create this bonus. Distinctive matching terms matter more than terms shared by nearly every supplied fact; repetition does not multiply the score. Exact evidence, conditions, kinds, task status and historical roles remain unchanged. Explicit owner questions retain the existing source-bound priority.

Explicit, fully supported information requests can now omit the unrelated fact tail. Every meaningful requested term must exist in full fact text/task titles, at least one must distinguish candidates, and whole actually admitted records must cover them all. Open tasks sharing even a common requested term remain candidates. Required pinned lore stays; stored records are never deleted. Unknown/ambiguous/pronoun/owner/action requests, ordinary narration and incomplete budget coverage keep the previous topical admission. Short recognized continuation has a [separate bounded balance](CONTINUATION-MEMORY.md). This does not guarantee that every recent fact or open task always fits.

This is lexical retrieval, not arbitrary semantic understanding. The original fixed synthetic corpus improves first-candidate and whole-request recall from24/48 to48/48. The independent48 admission cases include24 topical requests (32 needed records instead of192; whole-target recall20→24/24) and24 unchanged controls. Across the20 requests already containing all needed records, complete added prompts total77450→56353 characters (-27.2%). Live-model interpretation and native token usage remain separate checks. No new setting, model call, provider or stored lore edit is added.
