   `downloads/DeepRole-Brave-guided-start-20261019.zip`.

   Она включает предыдущие исправления памяти и скобок, а не только обучение.

## Что вошло в сегодняшнюю работу и передачу

Это сводка состояния, включая результаты живых проверок 19 октября.
Часть реализации RP323 была подготовлена раньше, а сегодня проверялась в игре.

### RP323: внеигровые ответы и старый прогресс среди повторов

- Pending-проверка ответа начинается до native GET, чтобы recovery/варианты
  не мигали на подтверждённом внеигровом ответе. Неизвестный результат и timeout
  освобождают интерфейс, но не дают права менять историю.
- Старые важные progress sources могут добавляться по целому названию задачи,
  статусу и подтверждённому владельцу. Прежняя содержательная память сохраняется;
  неполный набор не принимается. Обещания не выполняются автоматически.
- Live 19 октября: OOC → игровой шаг → OOC → reload прошли в тестовой мастерской.
  Это видимый smoke/DOM readback, не полный аудит DB или доказательство отсутствия
  любого однокадрового эффекта. Подробности в текущем большом handoff.

### RP324: компактная передача без потери выбранных данных

- `deeprole-memory-prefix-table-v1`: точные повторяющиеся префиксы и имена полей
  передаются таблицей. Формат принимается только при полном обратном
  восстановлении исходных значений и выигрыше размера всего запроса.
- Это упаковка, не удаление канона и не семантическое обобщение. Выборка памяти
  и хранилище не меняются из-за этого формата. Если невыгодно — старый формат.
- 144 сценария: сумма оценок добавок 348276 → 343156 tokens, −1,47%; не реальные
  API tokens и не размер одной игры. 9400 unit passed на том этапе.
- Live 19 октября: старый и новый независимый учебные наборы по 6/6 ответов,
  игровой кивок с вариантами и reload. Ввод был явным учебным сообщением:
  НЕ считать это доказательством автоматического извлечения всех фактов из лора.
  См. `RP05-REPEAT-PACKING-LIVE-20261019.md`.

### RP325: важное раньше доказанно пустых повторов

- Новый `story-repeat-selection.ts` предпочитает содержательные matching sources
  только перед строго подтверждёнными пустыми повторными репликами: точная
  цитата, доступный frozen speaker/episode и отсутствие новых действий,
  сведений и обязательств. Не угадывает пустоту по похожести текста.
- Всё необходимое помещается целиком, иначе exact prior fallback. Не сливает
  владельцев, обещания, условия, belief и completed. Составные действия без
  полного покрытия всех предметов пока остаются на прежнем пути.
- Независимый RU/EN набор с 0/80/400 повторов: 16/16 целевых вопросов/одиночных
  действий сохраняют 7 важных sources. На 36 сравнениях оценки 51878 → 42392,
  но некоторые полные запросы длиннее прежних неполных — это не ошибка само по себе.
- Полный unit на этапе RP325: 9529 passed, 5 прежних todo, 0 failed. Новый
  installed runtime RU/EN повторён по три раза: 6/6. Первые сбои ожидания stream
  закрыты исправлением harness, не ослаблением production guards.
- Loose QA assets перенесены из прежнего source ZIP в `tests/fixtures`
  байт-в-байт. Тесты не должны требовать старые удалённые файлы downloads.
- Личный DeepSeek live нового отбора RP325 ещё НЕ подтверждён. RP324 live его
  не заменяет. Старые 588 дополнительных записей не объявлены пустыми и не удалены.

### RP326–327: опциональные скобки и свежая политика перед отправкой

- В каждом мире отдельное правило, по умолчанию выключено. Целиком `[сообщение]`
  — OOC; скобки внутри игрового хода — пояснение. Обычный вопрос остаётся игровым.
  Явные OOC/manual режимы продолжают работать. Старые сообщения не пересчитываются.
- Реальный live RP326 не прошёл: whole-bracket сообщение получило игровой режим.
  Не выдавать этот результат за успех и не обвинять пользователя в выборе мира.
- RP327 воспроизвёл stale policy без уведомления: сохранённый флаг уже включён,
  а открытая страница держит старый snapshot. Перед REQUEST_CONTEXT перечитывается
  один выбранный world; обновляется только bracketedOoc. Scope/generation guards
  сохранены, игровой snapshot целиком не подменяется.
- Durable capture фиксирует purpose запроса: последующее выключение настройки
  не превращает уже отправленный OOC в игровой. Reload это сохраняет.
- RP327: 278 targeted/compat unit; production 24/24 (XHR/fetch × RU/EN ×
  managed/legacy/manual/cards-off/silent-setting + world UI 320/900).
  Личный live после этого исправления ещё нужно провести на обновлённой копии.
  Настройка/архитектура: `BRACKET-MESSAGE-MODE.md`.

### UX328: первое знакомство и настоящие переходы

- Приветствие из 3 экранов, сразу RU/EN, возможность пропустить. Install-only
  вкладка не открывается при update и не сбрасывает игру существующего пользователя.
- Книга в header, 8 глав / 31 шаг. В интерактивном шаге пользователь сам нажимает
  настоящую кнопку, обучение ждёт видимого назначения. Другой click не засчитывается.
  Информационные шаги имеют «Понятно, дальше».
- Пауза, resume/replay, сворачивание, keyboard/Escape/focus, reduced-motion.
  Tutorial progress отделён от лора и settings. Нет auto-click/submit/API,
  включения автоматической памяти или платной генерации за пользователя.
- Чужие редакторы и диалоги не закрываются: подсказка скрывается до их закрытия.
  Закрытый details не подтверждает переход даже при наличии layout box.
- Ограничено время чтения progress: зависшая optional read не держит App вечно
  в loader; поздний ответ не затирает текущую позицию.
- 200 targeted unit/component/startup; production 28/28 (4 guide + 20 bracket +
  4 world UI). После финального bounded-read guard повторены 4/4 guide, не все 28.
  RU/EN 320/900, дополнительно 320×520, scoped axe и screenshots. Все собственные
  браузерные профили закрыты. Личного live обучения и Firefox UI ещё не было.
  Контракт: `ONBOARDING.md`; визуальная система: `DESIGN-SYSTEM.md`.

## Что делать дальше — по приоритету

1. После подтверждения обновления пользователем — короткий live скобок:
   whole bracket → обычный ход с inline note → whole bracket → reload → обычный
   ход. Проверять purpose/плашку/варианты и отсутствие внеигровых эффектов, а не
   судить об успехе по вежливому стилю ответа DeepSeek. Старые неудачные отправки
   задним числом не переклассифицировать. Без update не объявлять повтор live новым.
2. Отдельно — первый пользовательский проход обучения через книгу, а welcome
   при необходимости только в отдельном чистом тестовом профиле. Не удалять
   основное расширение ради проверки. Объяснения должны соответствовать реальным
   подписям, подсказка не должна перекрывать целевую кнопку или стирать черновик.
3. RP-05: новые независимые формулировки и составные действия с полным покрытием
   ВСЕХ упомянутых предметов, включая персонажей вне сцены. Условия/исключения,
   частичное выполнение, разные владельцы и belief сохраняются целиком. Дальше
   при необходимости — отдельный live нового RP325 retrieval, не явного учебного ввода.
4. RP-08: replay/регрессии длинной игры — смена варианта, reload, продолжение в
   другом чате, защита ручных правок, дубли, stale responses и границы сохранения.
5. Firefox live, более широкий UX и наблюдение за кнопками вариантов у нижнего
   края/composer — отдельные незакрытые проверки, не обещания готового идеала.

Ни native context DeepSeek, ни бюджет одного запроса не стали безлимитными.
Подбор/сжатие снижают добавку расширения, но не доказывают автоматическую полную
память за пределами native history. Не обещать это пользователю без отдельного proof.
