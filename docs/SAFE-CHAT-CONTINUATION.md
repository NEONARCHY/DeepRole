# Продолжение в новом чате

## Что переносится

Кнопка сначала запрашивает проверку памяти. После подтверждения изменений — либо явного решения оставить память прежней — DeepSeek готовит сжимку последних сцен. Затем открывается новый чат. Сжимка добавляется скрыто к просьбе продолжить с того же момента.

У лора остаётся одна игра. Факты, авторы обещаний, исходные цитаты и ID источников, статусы дел, игровые сутки, отношения и ручные исправления сохраняются отдельно от сжимки. Она не становится новой записью канона и не завершает открытые дела сама.

Например: Нора обещала принести инструменты **только после разрешения**. Бумагу она уже принесла, а доставку краски отменила. После перехода инструменты остаются открытым делом, бумага — завершённым, краска — отменённым. Исправленное игроком местонахождение ключа сохраняется. Невыбранный вариант истории не присоединяется к текущей линии.

## Исправление RP275

Раньше при готовой сжимке мог дополнительно подставляться старый хвост переписки: автоматический fallback не отличал сжимку от отсутствующего переноса. При подключении нового чата общее recentStory тоже могло оставаться прежним. Теперь явный перенос определяет единственный сценический reference: сжимку или содержимое старого формата переноса. Новый сегмент получает этот reference; автоматический хвост его не дублирует.

Оригинальные сообщения, выбранные исходники и ссылки на них остаются в хранилище. Меняется только сценическая подсказка следующего сегмента, а не сыгранные факты. Для вручную подключённого чата без готовой сжимки прежний fallback сохраняется.

## Сбой и повтор

- До успешной отправки и локального подтверждения новое место не становится владельцем игры. Неудачная отправка не расходует сжимку; её можно отправить повторно.
- Перезагрузка не удаляет сохранённую сжимку. Автоматическая отправка в свежем чате имеет короткое окно безопасности; это не срок хранения самой сжимки.
- Запись нового владельца игры и квитанции переноса выполняется одной транзакцией. При ошибке записи исходное состояние сохраняется.
- Два параллельных переноса одной версии не могут оба переключить игру. Запоздалый перенос и настоящие изменения прогресса по-прежнему проверяются по общей ревизии.
- Повтор подтверждения уже применённого переноса не создаёт второй сегмент и не возвращает старые значения.

Если новый чат не открылся, сохранённая сжимка сама по себе не означает завершённый перенос. После сетевого принятия запроса всё ещё возможен локальный сбой сохранения; полной распределённой транзакции с серверами DeepSeek нет.

### Если сообщение принято, но перенос не сохранился локально

RP276 сохраняет в служебном состоянии вкладки ID сжимки, её токен и чат назначения перед локальной транзакцией. При её сбое видна плашка «Нужно завершить сохранение переноса» с кнопкой «Завершить сохранение переноса». Это отдельная ошибка сохранения, не ошибка генерации ответа.

Кнопка повторяет только локальную запись. Она не отправляет сообщение DeepSeek повторно. Плашка восстанавливается после перезагрузки этой вкладки; до завершения записи новая отправка из этого места приостанавливается. Исходный чат и сохранённые данные остаются доступны. Если прогресс действительно изменился в другом чате, прежние проверки ревизии не позволят применить устаревший перенос.

Эта квитанция не содержит текста лора и не меняет резервную копию мира. Она живёт в сессии вкладки; закрытие вкладки/всего браузера не даёт гарантии её восстановления. Сама сжимка хранится в библиотеке отдельно. Успешный HTTP-ответ означает принятие запроса, а не окончание генерации или проверку качества продолжения.

Если временно недоступна даже запись служебной квитанции, принятый адрес сохраняется в памяти открытой страницы до восстановления хранилища. Перезагрузка при полностью недоступном session storage не гарантирует восстановление этой отметки. Обычное автоматическое подключение нового чата не должно обходить ожидающий перенос. Новые отправки через fetch и XHR в этом месте приостанавливаются до завершения записи; это временная защита конкретного переноса, без изменения пользовательской настройки отправки без памяти.

## Границы проверки

Синтетические тесты используют вымышленную мастерскую: более 200 выбранных сообщений, ограниченный хвост истории, отдельный невыбранный вариант, подтверждённые роли/источники, три статуса задач, исправленное состояние и игровые сутки. Проверяются повтор, перезагрузка, сбой записи и две конкурирующие транзакции. Это регрессия механизма переноса, не оценка качества сжимки живой моделью. Полная история на сервере DeepSeek не сжимается и не удаляется этой доработкой; новый чат нужен именно для нового серверного окна.

Текущие результаты автоматических проверок и упаковки — в начале CODEX-HANDOFF.md и ROADMAP.md. Личный лор и установленная пользовательская копия для проверок не используются.

## English

An explicit handoff owns the next segment's scene reference: a compact recap or its explicit legacy transcript, without an additional automatic transcript fallback. The shared game's next baseline uses that reference; original story records, selected episode IDs, fact/source-role seeds, task statuses, game time, manual corrections, lore and images remain separate. Manual attachment without a prepared handoff retains its existing fallback. A failed send retains the queued handoff; acceptance and local ownership commit are separate stages. Native server history is not compressed or deleted. Tests use synthetic worlds and routed responses, not a live DeepSeek account or model-quality evaluation.
