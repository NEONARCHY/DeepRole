# Изображения в DeepRole

Необязательная функция для иллюстраций к истории. По умолчанию выключена. DeepSeek готовит визуальное описание выбранной сцены; решение по генерации принимает провайдер. Наборы «Обычные изображения», «Неоткровенная романтика» и «Откровенные сцены · 18+» различаются только тем, какое подключение и какие подписи они выбирают.

## Где брать изображения и API

Есть два независимых способа: **загрузить готовые картинки** — API не нужен; или **создавать новые внутри DeepRole** — нужен свой сервис изображений, возможна оплата.

Для аватарок подойдут ваши рисунки или портреты из веб-генератора, например [Adobe Firefly](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/generate-images-from-text-descriptions.html). Сохраните один базовый портрет и используйте его как референс для вариантов эмоций. Откройте **Персонаж → Изображения → Библиотека изображений**, загрузите PNG/JPG/WebP, назначьте эмоции и **Сохраните персонажа**. Это организация готовых картинок, не обучение модели и не повторная генерация. Качество загрузки задаётся в **Настройки → Оформление**; **Размер превью** в библиотеке помогает рассмотреть лица.

### Venice: простое подключение готового адаптера

Получите свой ключ в [кабинете API](https://venice.ai/settings/api); там же проверьте доступные средства и текущие тарифы. DeepRole не продаёт ключи и не включает бесплатную генерацию. [Официальная инструкция по аккаунту и ключу](https://venice.ai/blog/how-to-use-venice-api).

В **Настройки → Изображения → Добавить подключение** заполните поля:

| Поле | Что указать |
| --- | --- |
| Название подключения | Понятное вам название, например «Мой сервис изображений». |
| Формат API | **Venice native API**. |
| Адрес API | `https://api.venice.ai/api/v1`, без окончания `/models` или `/image/generate`. |
| Ключ API | Ваш личный ключ; нажмите **Сохранить ключ**. |
| Доступ к API | Нажмите **Разрешить доступ к API** для этого адреса. |
| Модели | Нажмите **Загрузить модели**; выберите модель генерации и модель редактирования для загруженных лиц. |
| Количество референсов | Подтверждённый лимит выбранной модели, не цифру из рекламы другой модели. |
| Дополнительные параметры · JSON | Сначала `{}`. Добавляйте только параметры из документации именно вашей модели и операции. |

Включите подключение и нажмите **Сохранить подключение**, назначьте его выбранному набору, включите генерацию и сохраните настройки изображений. Идентификаторы моделей и известные возможности приходят из живого каталога, не из этой инструкции. [Официальный каталог](https://docs.venice.ai/api-reference/endpoint/models/list), [документация редактирования по референсу](https://docs.venice.ai/api-reference/endpoint/image/edit).

Для похожего лица назначьте **Постоянный референс** в **Изображениях** каждого персонажа, опишите внешность и выберите модель, работающую с референсами. Без назначенного фото остаётся текстовое описание, одинаковое лицо не гарантируется. Для групповой сцены нужен достаточный лимит референсов. Качество сохранённой аватарки и разрешение результата — разные настройки: параметры результата API задаются в JSON подключения, не в качестве загрузки.

### Другие API и частые ошибки

Для [OpenAI Images API](https://developers.openai.com/api/docs/guides/image-generation) выберите одноимённый формат, адрес `https://api.openai.com/v1`, свой API-ключ и доступную вашему аккаунту модель изображений. Адаптер поддерживает и совместимые сервисы изображений, но одной совместимости с чатами недостаточно. Не вставляйте логин сайта или пароль подписки на чат вместо API-ключа.

Если не работает, проверьте включение подключения и генерации, назначение сохранённого подключения набору, сохранение ключа, разрешение доступа и поддержку нужной операции моделью. Модель рисования по тексту может не принимать фото. Откройте **Подробности ошибки** под красным сообщением: там этап, код DeepRole и HTTP-статус, когда он доступен. Ключ не раскрывается, платный запрос не повторяется. Тарифы, модели и правила содержания могут меняться — сверяйтесь с официальной документацией, не копируйте устаревшие названия.

## Подключение

Кнопка **Создать иллюстрацию** появляется только после полного завершения ответа DeepSeek, включая скрытые технические блоки. Кнопка, подготовка кадра и готовое изображение находятся под сюжетным ответом, перед вариантами действий. Закрепление вариантов не переносит иллюстрацию в плавающее окно; она остаётся рядом со своей сценой.

Все карточки иллюстраций — готовые изображения, ожидание и ошибки — совпадают по ширине и горизонтальным границам с вариантами ответа. Это относится и к изображениям в предыдущих сообщениях. Изменение окна, поля ввода или закрепления автоматически обновляет раскладку. Если вариантов ещё нет, используется ширина поля ввода, закреплённого у края окна; без такого поля и вариантов — ширина сюжетного сообщения. Это только размер карточки на экране, не изменение разрешения сохранённого изображения.

Откройте **Настройки → Изображения**. Добавьте название, адрес своего API и его формат. У DeepRole нет встроенного провайдера, каталога моделей, цен или тарифов. Сохраните ключ отдельно, разрешите доступ к указанному адресу, включите подключение и загрузите модели. Выберите модель, сохраните подключение и назначьте его нужному набору настроек.

**Модель генерации** используется без референсов. **Модель для референсов** — для редактирования по загруженной картинке; обычная модель генерации не обязательно это умеет. После загрузки каталога Venice эти списки разделены по данным API. Если ранее была сохранена неподходящая модель, DeepRole предупреждает, но не меняет её за вас. Когда API не сообщает возможности модели, они не угадываются.

Наборы только выбирают подключение и подписи. Они не запускают анализ текста и не меняют параметры запроса скрытно. Добавление набора разработчиком — одна запись в `IMAGE_CONTENT_LEVELS`: тип, проверка и оба перевода выводятся из неё. Набор «Откровенные сцены · 18+» сохраняется только вместе с подтверждением возраста в этом же разделе; без подтверждения он не записывается и запрос по нему не отправляется.

Как обходятся с взрослым контентом, решает провайдер и ваше законодательство, а не DeepRole. У многих API взрослый результат размывается служебным параметром по умолчанию, а фильтры хостинга могут отказать даже у расцензуренной модели: расширение показывает такой отказ человеческим текстом и не пытается его обойти. Персонажи должны быть вымышленными; реальные люди недопустимы.

Дополнительные параметры — JSON-объект, до 32 полей и 32 000 символов. Неизвестные поля сохраняются и передаются без изменений, без списка разрешённых параметров. Нельзя подменить служебные `model`, `modelId`, `prompt`, `image`, `images`, авторизацию или заголовки: такой профиль будет отклонён целиком, а не незаметно исправлен. Документированные параметры конкретной модели, включая её служебные флаги, задаёт владелец расширения — в том числе через это поле. Seed можно задать в JSON дословно; если одновременно указан постоянный seed персонажа, запрос отклоняется до отправки, без перезаписи одного значения другим. Новых зависимостей нет.

Ключ хранится в отдельной записи `storage.local`, **без шифрования сейфом**. Его видит фоновая часть расширения, но не наш код страницы DeepSeek. Интерфейс показывает только последние четыре символа. Ключи и текущие подключения не входят в резервные копии или пакет мира: на другом компьютере подключение нужно настроить заново. Снимок повтора изображения содержит исходные несекретные адрес API, модель и параметры; импорт не включает подключение и не запускает запрос. Обычный HTTPS обязателен; HTTP допускается только для localhost.

## Создание иллюстрации

Скрытые служебные сообщения не оставляют пустых плашек: DeepRole убирает их оболочки, отступы и кнопки DeepSeek. Полезные карточки, изображения и сюжет остаются на экране. Это только оформление — исходный текст сохраняется в истории, расширение по-прежнему читает ответы. Место над полем ввода, необходимое для закреплённых вариантов, сохраняется.

Нажмите **Создать иллюстрацию** под завершённым ответом. Сразу появится карточка загрузки; DeepSeek скрыто подготовит описание именно этого кадра и всех действительно присутствующих участников. Для каждого укажет внешность, действие, положение и фокус. Он получит текст ответа, анкеты, подсказки к референсам и их допустимое количество, но не изображения или ключи API. Служебный запрос не продолжает игру и не меняет лор. Черновик, другой служебный запрос и незаконченный ответ блокируют подготовку. Некорректный план останавливается до платной генерации.

В групповой сцене каждый участник получает своё назначенное изображение, пока позволяет **Количество референсов** подключения: например, шесть участников и лимит шесть — шесть референсов; три участника — три. Важный собеседник получает приоритет. Второстепенные люди могут быть в мягком фоновом размытии, но остаются частью кадра; при совместном взаимодействии инструкция просит сохранять участников различимыми. Эти правила одинаковы для обычных и неоткровенных романтических/пикантных кадров, без отдельной сексуальной механики. Номер референса явно связан с именем: лицо, внешность и тело не должны «перепрыгивать» между людьми; одежда, действия и позы берутся из сцены, не копируются автоматически с портрета.

Если лимита или назначенного изображения не хватило, персонаж не исчезает: остаётся его текстовое описание. В **Описание и участники** показано, кому приложен референс и кто описан без него. В настройки лимита не вшиты названия моделей; API сообщает известные пределы, а неизвестный предел нужно проверить в документации подключения. Локальная защита допускает до 40 участников и ограничивает общий размер текста: это не обещание возможностей модели. Фактическая анатомия, точность действий и внешность зависят от генератора; инструкция и изображения помогают, но не гарантируют результат.

Необязательный **Стиль изображений** задаётся один раз в **Настройки → Изображения**. В **Персонаж → Изображения** закрепите два образа: **Нейтральный** и **Пикантный**, при желании подпишите, когда использовать каждый. Для обычных сцен выбирается нейтральный. Если другого образа нет, используется нейтральный; без референсов — текстовая внешность. Несколько референсов отправляются в порядке важности персонажей, в пределах возможностей настроенной модели; описание всех выбранных участников остаётся в запросе. Qwen Image Edit назначается моделью для референсов. Провайдер получает только описание кадра, выбранные изображения и параметры.

По умолчанию иллюстрации запрашиваются в **16:9**, сгенерированные селфи — **9:16**. Явно заданные `size`, `width`, `height`, `aspect_ratio`, `resolution` в дополнительных параметрах передаются без перезаписи. Полный результат сервиса сохраняется без уменьшения и обрезания: маленький вид в чате — только превью. Под снимком показаны реальные пиксели; нажатие открывает большой просмотр с масштабом 100%. Старые изображения, уже уменьшенные до 768×432 / 432×768, восстановить автоматически нельзя. Референсы для отправки по-прежнему уменьшаются до 1,5 млн пикселей и меньше 10 МБ; это не ограничение качества готового результата.

Один готовый снимок ограничен 10 млн символов в локальном кодировании (около 7,5 МБ файла). Вмещающийся PNG/JPEG/WebP сохраняется байт-в-байт. Более тяжёлый результат допускает только качественное JPEG-сжатие без изменения пиксельных размеров; если он всё ещё не помещается, выводится явная ошибка вместо скрытого уменьшения. Для нового результата заранее проверяется запас 10 млн символов плюс референсы в общем бюджете мира; бюджет не повышается и старые данные не удаляются. По [документации Venice edit](https://docs.venice.ai/api-reference/endpoint/image/edit), параметр `resolution` и допустимые 1K/2K/4K зависят от модели; повышение разрешения или тарифа DeepRole автоматически не включает.

**Попробовать ещё раз** использует сохранённые описание, модель, seed, остальные параметры и нормализованные референсы первой попытки. Повторно спрашивать DeepSeek и брать изменённый стиль или новые фото не требуется. Повтор иллюстрации показывает ожидание и новый результат **в той же карточке**. Кнопки назад/вперёд листают сохранённые результаты только этого сюжетного ответа, без API и оплаты; стрелки клавиатуры работают при фокусе на панели истории. Во время ожидания и после ошибки можно посмотреть прежний снимок. Новый готовый снимок открывается автоматически; после перезагрузки показывается последний результат или последняя ошибка. Удаляется только выбранный снимок. Повтор селфи по-прежнему заменяет это селфи. У старых изображений без сохранённого запроса есть объяснение недоступности повтора. Ошибки показаны в карточке; перезагрузка не делает новый платный запрос автоматически. Каждый ручной повтор может стоить денег. После таймаута провайдер мог уже обработать запрос: проверьте расходы. Изменение исходного адреса или протокола API блокирует точный повтор. Ключи API не входят в снимок запроса.

Иллюстрации сохраняются отдельно от портретов, привязаны к конкретному ответу, входят в полный бэкап и экспорт мира. Пакет мира сохраняет исходную привязку к чату: это архив изображения, а не перенос его на одноимённый ход нового чата. До 60 иллюстраций на мир; общий бюджет изображений мира, включая портреты и селфи, — 50 МБ в используемом локальном кодировании. Переполнение не удаляет старые данные. Удаление иллюстрации не меняет лор или отправленный ответ. При включённом сейфе изображения защищаются вместе с остальными записями.

Если результат приходит ссылкой на другой домен, появится кнопка загрузки готовой картинки. Она открывает отдельную вкладку расширения для разрешения домена. Это загрузка уже готового файла, **не повторная генерация**. Временная привязка живёт до 15 минут в сессии и при включённом сейфе зашифрована.

## Проверенные форматы API

Контракты сверены 8 октября 2026 года на живом каталоге моделей; предел мультиредактирования дополнительно пересверен 9 октября по документации Venice. Названия ниже обозначают форматы адаптеров, а не предустановленные подключения.

- OpenAI Images: [генерация](https://developers.openai.com/api/reference/resources/images/methods/generate) и [JSON-редактирование](https://developers.openai.com/api/reference/resources/images/methods/edit). Референсы передаются в `images[].image_url` как data URL. Ответ — JSON с base64 или ссылкой. [Список моделей](https://developers.openai.com/api/reference/resources/models/methods/list) не сообщает цены и возможности изображений: TODO для документированного расширения метаданных; неизвестные значения не выдумываются.
- Venice native: [генерация](https://docs.venice.ai/api-reference/endpoint/image/generate) — JSON с `images[]` или документированный бинарный режим; [редактирование одной картинки](https://docs.venice.ai/api-reference/endpoint/image/edit) и [нескольких](https://docs.venice.ai/api-reference/endpoint/image/multi-edit) — сырые байты изображения. Несколько референсов уходят как data URL в JSON. **Для одного референса используется документированный raw base64 в JSON**: поддержка data URL этим отдельным маршрутом не подтверждена, TODO до уточнения контракта.
- [Список моделей Venice](https://docs.venice.ai/api-reference/endpoint/models/list) читается из API, включая цену, приватность, предел описания и признак расцензуренности. Цена у Venice лежит не в одном поле: у генерации и правки она вложена в режим (`pricing.inpaint.usd`, `pricing.resolutions.1K.usd`), поэтому DeepRole берёт наименьшую документированную сумму модели и не выдумывает её, если API не сообщает ничего. По текущей [документации multi-edit](https://docs.venice.ai/api-reference/endpoint/image/multi-edit) предел входных изображений зависит от модели и читается из `capabilities.maxInputImages`. Один признак `constraints.combineImages` не позволяет вывести число: неизвестный предел не подменяется прежней догадкой «3». После загрузки моделей выбор модели для референсов подставляет известный предел; старое сохранённое значение можно изменить вручную и сохранить подключение. Модели правки приходят из запроса `type=inpaint`, обычной генерации — из `type=image`.

Совместимый API должен поддерживать выбранный протокол. Если он требует multipart вместо JSON или иной маршрут, адаптер не угадывает формат. Модель может игнорировать seed или не сохранять внешность идеально; референсы помогают, но не дают гарантии.

## Ошибки и информация сервера

400 — параметры запроса; 401 — ключ; 402 — баланс; 403 — доступ запрещён; 404 — модель или адрес не найдены; 413 — слишком большой запрос; 415 — формат; 429 — подождите; 500 — сбой; 503 — модель занята. Ошибки не вызывают повторную генерацию. Сам по себе HTTP 403 не доказывает отказ из-за содержания: причина может быть в правах ключа. Три заголовка Venice сохраняются и показываются. Если API не сообщает цену, возможности редактирования или пределы модели, DeepRole не придумывает их; для числа референсов исходный запасной вариант — 1.

Наведите мышь на красный текст для короткого кода или откройте **Подробности ошибки** — этот пункт доступен и с клавиатуры. Там видны этап сбоя, HTTP-код, отправленная модель, путь запроса, сообщение и код провайдера, если он их вернул, и названия проблемных полей. Отсутствие описания кадра от DeepSeek отделено от ошибки API изображений. Просмотр не обращается к модели и не стоит денег. Диагностика иллюстрации остаётся после обновления страницы; старый ответ, который предыдущая версия отбросила, восстановить нельзя.

Читаются только документированные поля JSON, без полного тела запроса или HTML. Ключ, изображения и исходный текст вычищаются из диагностики. Большие, повреждённые и неизвестные ответы сохраняют HTTP-код без необработанного тела. После исправления подключения нажмите **Создать иллюстрацию**: **Попробовать ещё раз** намеренно отправляет прежнюю модель и параметры первой попытки. После таймаута сначала проверьте списания у провайдера.

## Проверка реализации

Этап 1: каркас, отдельное хранение, интерфейс, строгая проверка, лимиты и экспорт. Этап 2: сетевые адаптеры, модели из API и обработка JSON/бинарных результатов. Для обоих этапов отдельно выполняются TypeScript и полный набор unit/integration-тестов. Внешние запросы в автоматических тестах подменяются. Живую платную генерацию без ключа и согласования расходов не считаем проверенной.
