# RP387 — повторный перенос из сохранённой памяти

Ожидания закреплены 17 ноября 2026 **до первого запуска**. Синтетические
ответы, вымышленные персонажи, изолированный Edge; живой аккаунт не используется.

Матрица: RU/Fetch и EN/XHR × automatic/review × обычный первый ответ
третьего чата / перезагрузка во время первого ответа. Всего восемь сценариев.

1. Исходный чат A недоступен. Через штатный просмотр сохранённой сцены
   открыть B без модельного запроса в A. В B сыграть два хода: жетон в медной
   коробке, затем деревянная печать в зелёном ящике. Условное обещание отдать
   фонарь остаётся на проверке. Automatic сохраняет два обычных факта;
   review оставляет все три предложения на проверке.
2. B тоже становится недоступен: история отвечает 403. Просмотр переноса
   показывает последнюю записанную сцену с печатью, а не исходную сцену A.
   Открыть C без модельного запроса в B и без изменения текущей игры до ответа.
3. Первая реплика C сохраняется точно, без служебных вставок в журнале.
   В отправленном контексте есть последняя сцена и, в automatic, оба факта.
   Первый ответ C добавляет факт о синей ленте в латунной шкатулке.
4. При перезагрузке C до окончания ответа перенос восстанавливается только
   по точной полной первой паре из истории. Автоматического повторного POST нет.
5. Игра и её ID общие; активен C. Прежние ревизии B и ID очереди сохраняются.
   В automatic три факта и одно предложение на проверке; в review нет
   принятых фактов, четыре предложения на проверке. Дубликатов нет.
6. Следующий обычный ход C использует накопленную память. Его ответ не добавляет
   новых фактов; reload оставляет восемь ревизий (четыре пары), те же факты
   и очередь. Всего четыре явных POST — два в B и два в C, ни одного в A.
7. Обновление старых A/B не меняет активный чат, память или очередь; оба
   показывают, что игра продолжена в C. Новый черновик C сохраняется.

Полный исправленный стенд на RP386: 4/8 проходят (review), 4/8 automatic
не сохраняют новый факт C. Диагностика показывает ложный конфликт между
«деревянная печать в зелёном ящике» и «синяя лента в латунной шкатулке»:
общие имя/глагол/предлог и разные цвета считались противоречием независимо
от предмета. Память до переноса и сама очередь не потеряны.

До первого запуска дополнительных модульных контролей закреплено: простые
одиночные действия с явно разными предметами не конфликтуют только из-за
цвета. То же для RU/EN и обратного порядка сравнения. Смена цвета одного
предмета/его места, цвет глаз, числа, отрицание, местоимение вместо предмета
и явно заявленный моделью конфликт по-прежнему требуют проверки.

## Исправление

`conflictingStoryText` больше не сравнивает цвета разных предметов в простой
одиночной конструкции «кто положил предмет в/на/под место». Проверка ограничена
явно разными названиями предметов у одного действующего лица; сложные фразы,
местоимения и неизвестная форма сохраняют прежнюю осторожную проверку.
Числа и отрицание проверяются отдельно; явный `risk: conflict` не обходится.
Никакие сохранённые записи и решения прежней очереди не переписываются.

В отдельном отрицательном контроле до исправления 3/16 модульных сценария
выявили ложное предупреждение; остальные, включая защитные проверки, прошли.
Два теста повторного переноса в хранилище уже проходили: ошибка зависит от
набора прежних фактов и воспроизведена полным браузерным сценарием, а не самим
количеством переносов. Добавлены два контроля неоднозначной/составной фразы.

Итоговые модульные проверки: **534/534**, 24 файла, Node 24.22.1,
`--maxWorkers 2`, 28.53 секунды. Нагрузочный тест 100 порций истории проходит
без одновременного запуска браузерных наборов. TypeScript прошёл.
