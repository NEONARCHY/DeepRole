# Проверка ограничений веб-чата DeepSeek — 16 ноября 2026

Проверена сборка RP356 (`a1716cd`): каталог Chromium побайтово совпадал с архивом выпуска. Браузерные прогоны использовали отдельные профили Edge и локальные ответы на запросы к DeepSeek. Число 40 000 и HTTP-коды — параметры стенда, а не подтверждённый контракт DeepSeek. Живой аккаунт и личный лор не использовались.

| Сценарий | Что делает RP356 |
| --- | --- |
| История старого чата читается, отправка служебного запроса возвращает 403 | Штатный перенос останавливается на проверке памяти. Новый чат и снимок переноса не создаются. Сохранённая запись памяти и привязка игры остаются на месте. |
| Первый запрос в новом чате возвращает 429 после смены URL | Отправка не дублируется. Снимок переноса остаётся неприменённым; активным остаётся старый чат. |
| Итоговый текст из реплики, памяти и служебного разделителя: 39 999 / 40 000 / 40 001 символ | Все три запроса отправляются по одному разу с исходной репликой. Стенд отклоняет последний (413): предварительной проверки этого порога в RP356 нет. |
| Служебный запрос возвращает 403, 413 или 429 | Транспорт сообщает об отказе один раз и передаёт ответ браузеру. Автоматического повтора нет. |
| В чистом чате вручную выбран тот же мир | Сохранённая запись мира подключается к первым двум репликам и после перезагрузки (fetch и XHR, RU/EN). Этот сценарий не восстанавливает отсутствующую последнюю сцену. |

Результат: TypeScript без ошибок; 200 тестов Vitest прошли в 10 выбранных файлах на Node 24. В Edge прошли 22 сценария переноса и 4 сценария ручного подключения мира (RU/EN). Браузерные сценарии воспроизводятся после сборки Chromium:

```powershell
npx playwright test -c playwright.extension.config.ts continuation-chain-runtime.spec.ts --workers=3
npx playwright test -c playwright.extension.config.ts new-chat-memory-runtime.spec.ts -g 'memory clean/' --workers=2
```

## Следующая работа

1. Проверить и реализовать явное продолжение из локальной памяти без запроса в старый чат. Показать, до какого момента есть сохранённые данные, и не выдавать старую сводку за последнюю сцену. Переключать активный чат только после подтверждённой отправки в новом.
2. Проверять длину итогового текста перед отправкой с запасом до наблюдаемого порога; при нехватке места сначала убрать необязательную память или объяснить, что мешает. Не обрезать реплику пользователя. Учесть обычный ввод и служебные запросы (сводка, подготовка анкет, сброс).
3. На тестовом аккаунте отдельно подтвердить вид отказа (HTTP, ошибка внутри успешного HTTP-ответа или заблокированный редактор). Не принимать числовой порог или срок простоя за универсальное правило.

Код расширения и архивы на этапе этой проверки не менялись. Реализация резервного переноса описана в [RP357](RP357-SAVED-MEMORY-CONTINUATION-20261116.md).
