## Конкретные потери

В пекарне Зоя обещает доставить запечатанный сахарный ящик С-29 после проверки пломбы. Он хранится в холодной кладовой, куда пускает заведующая; груз теперь принимают у подъёмника. На прямой вопрос с названием находятся все четыре нужные записи. На «Как там отправка сладкого груза с целой пломбой…» по-русски пропущены кладовая/разрешение заведующей и новое место приёма. На «Что с тем обещанием?» даже после принятого уточнения про этот ящик теряется запись о доступе. В английских вариантах этого сюжета теряется условие доступа a1. Бюджет16000 не исчерпан: проблема не в длине окна.

На леднике обе перефразировки теряют a1/a2: морозильный бокс/доступ врача и новое место приёма на верхней площадке. Прямая короткая ссылка проходит по-русски, но по-английски теряет a1. В планетарии русская перефразировка теряет a1/a2/a3: аппаратная/хранитель, новый кабинет приёма и отсутствие доставки; английская — a1/a2. Короткие ссылки на обоих языках теряют a1. Причина в конкретном matcher пока не доказана; первый результат не заменяется исправленным отчётом.

## Неопределённость и сохранность

Все42 запроса с ожидаемой неопределённостью получили UI coverage unverified; **ложных complete относительно целевого gold —0**. В30 из42 также есть explicit reference guard в подготовленном запросе. В12 остальных — подмена владельца и несуществующий предмет, по всем3 сюжетам RU/EN — guard отсутствует. Это отдельный недостаток предупреждения для модели, не подтверждённое назначение вещи чужому человеку: переданные роли не исказились.

Без принятой связующей реплики, с ложным уточнением только в raw recent, с двумя самостоятельными упоминаниями похожих названий и с неизвестным raw продолжением guard/unverified сохранены во всех24 controls. Местоимение не объявлено доказанной личностью объекта. Дополнительные реальные кандидаты публикуются в report, но audit не оценивает полезность каждого из них.

Во всех96 запросах нет обнаруженных изменений/выдумывания text, точной quote, kind, task/claim, роли, revision ID, episode/period или persistent status. Старое место aOld и открытые superseded c0/d0 не передаются. Нет duplicate sources, изменения input/draft/canon, расхождения cold/warm output/coverage или optional overflow относительно полного added-context meter.

## Воспроизводимость и границы

Три новых сюжета — пекарня, ледниковая экспедиция, планетарий; доставка/ремонт/оплата/сопровождение/неразглашение вместо повторения одних возвратов. Это agent-authored synthetic accepted-memory audit: общий каркас, переводы и повторяемые фоновые сцены коррелируют.96 запросов не являются96 независимыми мирами; их проценты не сравниваются как улучшение/ухудшение относительно RP287. Новые примеры после этого замера уже seen.

Данные/gold закреплены до compiler. Предварительная регистрация ошибочно ссылалась на старый runner: initial manifest и preflight snapshot сохранены. До первой оценки создан v2 manifest с правильным собственным runner fingerprint; все input/gold/rows/runtime прежние. [Протокол](MIXED-OBLIGATION-EVALUATION.md).414 fingerprints и SHA256 seal позволяют проверить сохранность первого результата. Старые RP283/RP287 reports/seals не менялись. QA/упаковка фиксируются в актуальном начале CODEX-HANDOFF.

Рабочий runtime, UI, хранилище, настройки, модель и личный лор не изменялись. Live DeepSeek/браузерная отправка/полный E2E в этой итерации не запускались. Повторение требует Git checkout с tests; `--freeze`/`--evaluate` отказывают при существующем baseline/report, первый результат нельзя удалять ради повторного запуска.

## Следующая задача

Исследовать11 потерь: сначала условия доступа a1 по exact accepted bridge для доставки, затем перефразировки a1/a2/a3. Отдельно расширить проверяемое предупреждение для подмены владельца/несуществующего предмета без угадывания объекта. Не добавлять условие из соседней чужой вещи и не превращать разрешение на ремонт/перевозку в согласие раскрыть секрет. Изменение runtime — следующий этап с отдельным seen report на этих данных и регрессом старых RP283/RP287; затем снова нужен новый независимый набор. RP-05/general semantics/true cross-turn delta остаются открыты.
