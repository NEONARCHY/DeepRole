# Короткие ссылки на долги — исправление RP288

RP291: [предпосылка вопроса не доказывает владельца или предмет](OBLIGATION-PREMISES.md).12missing premise warnings исправлены без изменения прежних source selections;метерированный guard не является retrieval reference и не создаёт новую связь в памяти.

Актуальное дополнение RP290: [условия доставки и ремонта](MIXED-OBLIGATION-REPAIR.md). Поддержаны prose delivery/repair,вопросы об отправке и EN leading known-name possessive. Для short reference четыре candidate label slots считаются после accepted-scene scope;посторонние старые labels их не занимают. Scan16tasks/128rows/whole budget прежние. Описание исходного RP288 ниже сохранено как история.

## Что изменилось для игрока

После «Что там с её обещанием?» или “Remind me of this promise” DeepRole теперь добавляет в скрытый запрос явное предупреждение: ссылка не установлена автоматически, по общему названию нельзя угадывать предмет или владельца. Локальный статус сообщает, что полнота подбора для этой формулировки не подтверждена, даже если подготовлены все доступные кандидаты. Это описание ограничений подбора, не запрет отвечать и не запрос к модели для разрешения местоимения.

Такой статус сам по себе не означает потерю памяти: найденные записи уже приложены к запросу. DeepRole предупреждает, что фраза «то обещание» не доказывает, какую именно из похожих договорённостей вы имели в виду.

Например, в истории два «старых бархатных плаща»: один обещали вернуть после спектакля, другой — после фотосъёмки. Их отдельные записи, бирки, условия и владельцы передаются целиком. Общее название не превращает их в один предмет. Чистка плаща не закрывает долг; выполненные и отменённые обязательства сохраняют исходный статус.

## Причина найденных пропусков

В RP287 из заголовка выполненного долга про «белый керамический поддон» извлекался общий префикс «белый керамический»: полное название уже не повторялось ещё в двух текущих записях, зато эти два слова встречались в других предметах. Такой префикс конкурировал с «белый керамический горшок» внутри одной и той же реплики и блокировал подбор. В EN theatre происходило обратное: расширенное «old velvet cloak belonging…» не совпадало со сценическим «old velvet cloak tagged…», а слишком общая пара «old velvet» подтягивала также жилет и занавес.

Теперь для **уже подтверждённого источниками** префикса полного заголовка выбирается самая длинная его буквальная часть, присутствующая одновременно в принятом тексте сцены и его точной цитате. Минимум остаётся два значимых слова. Короткое совпадение отбрасывается только там, где его конкретное вхождение полностью покрыто более длинным названием в той же части текста. Если короткое название встречается ещё и отдельно, неоднозначность сохраняется. Это не определение части речи и не семантическая модель.

Одинаковые эффективные префиксы объединяют список **кандидатов**, сохраняя все исходные task IDs, owner roles и источники. Остаток raw сцены может только отменить narrowing: неизвестное второе обещание, другое название или неподтверждённый bridge не становятся положительным evidence.

## Защита при отказе

Раньше explicit guard добавлялся только при успешном дополнительном подборе. При отказе matcher возвращался предыдущий контекст, который иногда сообщал complete и не предупреждал модель об unresolved ссылке.

Теперь распознавание поддержанного short-reference intent выполняется **до всех проходов выбора**, в `compileGameContextPass`. Guard входит в обязательную часть и whole token meter; budget/source/capacity fallback возвращает уже защищённый предыдущий контекст. При нехватке места не дописывается неучтённый текст поверх лимита. Required-overflow продолжает иметь приоритет над другими статусами. Опция `referenceRecall:false` сохраняет явное отключение этой обработки.

Пределы16 текущих return tasks/4 исходных label groups/128 транспортных строк, source binding, episode scope, точная цитата, проверка ролей и source budget остались. Старый literal matcher по-прежнему вызывается первым. Для поддержанной короткой ссылки на обещание даже его успешный подбор сохраняет unverified/query, потому что буквальный label не доказывает единственную личность предмета.

- Отдельный [seen report RP287](benchmarks/rp288-rp287-reference-seen-results.json):26 output changes,7 coverage changes. В EN theatre больше не добавляются c1/c2 про посторонний выполненный возврат жилета; это **2 retrieval omissions относительно прежнего слишком широкого подбора**, а не удаление из канона. Их исключение явно отражено в lostPriorFacts=2. Все требуемые gold записи и предыдущая текущая selection сохранены; остальные82 outputs и все6 budget probes прежние.
- На прежнем RP283: **54/54**,312/312,0missing/integrity/prior loss/control drift;1 reference output изменён,83 прочих outputs и вся coverage прежние. Все24 rejection controls сохранены. [Seen report RP283](benchmarks/rp288-rp283-reference-seen-results.json).
- Первые независимые reports RP28758/62 и RP28339/54, frozen inputs/gold/protocols/seals остаются неизменными. Это **seen regression после исправления**, не новый независимый результат и не замер ответа DeepSeek.

## Оставшиеся границы

Не обещаются любые местоимения, произвольная морфология, распознавание всех видов обязательств, разрешение владельца по полу/имени предмета или понимание любого перефразирования. Поддержанный intent ограничен существующим распознавателем. Общие префиксы могут расширить список настоящих кандидатов; explicit guard запрещает выдавать их общность за object ID. Если несколько независимых вхождений не позволяют выбрать единственную подтверждённую группу, остаётся предыдущий защищённый подбор.

Следующий независимый audit должен использовать новые сюжеты и формулировки, разные самостоятельные вхождения общих названий и обещания других типов. RP-05, общий semantic поиск и true cross-turn delta этим изменением не закрываются. Подробные автоматические/native проверки и ограничения — в [QA](benchmarks/rp288-qa-results.json). Личный лор и установленный пользовательский профиль не изменялись.
