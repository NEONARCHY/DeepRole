## RP356 — вкладка меню и восстановление состояния подготовки

21 октября 2026. Пользователь сообщил: после смены вкладки меню теряет статус,
служебное окно остаётся на «Ожидаем ответ», хотя job уже error/cleanup failed
и содержит 3 подготовленные анкеты. Исправленная stats-ошибка из журнала —
не доказательство текущей причины остановки. Старый диагностический экспорт
вообще не содержал job.error; точную причину этого конкретного запуска не установили.

Исправления кода:
- Embedded App читает вкладку своего iframe через DR_MENU_TAB/sender.tab.id,
  а не активную вкладку/окно. Тот же адресат используется для действий App.
  Самостоятельная панель сохраняет выбор текущей активной вкладки.
- Возврат видимости/фокуса обновляет контекст меню и сохранённый reset job.
- Cast worker получает read-only status своей задачи каждые20сек и при возврате.
  Конечное состояние останавливает ожидание; ошибка потери ownership показывает
  проверку временного чата, не запускает новый запрос и не разрешает удаление.
- Временное окно и карточка подготовки показывают число сохранённых анкет.
  Cleanup ловит исключения и завершает экран состоянием cleanup-failed.
- Таймаут ответа:7мин видимого времени, до30мин скрытого на один ответ;
  после возврата есть минимум15сек для отрисовки, прежний checkpoint сохранён.
  Это не гарантия работы при заморозке браузера/сне ОС.
- Диагностика v3: текущий безопасный код ошибки, updatedAt, build timestamp.
  Лор/ответы/источники не добавлены в экспорт. Два подтверждения сброса,
  exact binding, ownership, проверка ответа и запрет дублирования отправки сохранены.
