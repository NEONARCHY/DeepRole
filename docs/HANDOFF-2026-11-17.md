| RP384 | Копия реплики и доказательство её отправки сохраняются до POST. После ухода со страницы можно проверить точную завершённую пару по истории и закончить перенос без повторного запроса модели. При недоступной истории есть ручная проверка. |
| RP385 | Восстановленная первая пара и перенос сохраняются одной транзакцией. Первая сцена получает инструкцию автоматической памяти; обычные факты сохраняются, спорные поступают в очередь. Сбой базы откатывает всё. |
| RP386 | Тот же путь действует при обычном переносе без reload. Следующий ход получает новый факт. Назначение первой реплики фиксируется до отправки: позднее изменение настройки скобок не превращает игровой ход во внеигровой и наоборот. |
| RP387 | Проверен повторный перенос A → B → C при недоступных старых чатах. Исправлено ложное противоречие цветов для явно разных предметов; проверки одного предмета, отрицаний, чисел и неоднозначности сохранены. |

доступные разрешённые возможности заново; не обещать, что меню уже исправлено.
Обычные HTTPS-виджеты доступны независимо от доступа к меню.

Сетевые отказы, недоступный старый чат, длинные запросы и ошибки хранилища в

1. Проверить рабочее дерево и выполнить `git pull --ff-only` в `main`, не

3. На живом HTTPS-чате проверить прямой переход из старого чата: предпросмотр
   последней сцены → главная с плашкой готовности → reload → первая обычная
   реплика → записанная сцена/новый факт → следующий ход → reload. Старый чат
   должен ссылаться на новый. Не отправлять подготовительный запрос в старый чат.
4. Проверить уменьшение подключённой памяти без удаления записей, повтор после
   локального отказа по длине и сохранение выбора после reload. Не создавать
   реальные ошибки квот аккаунта специально; для отказов есть локальные тесты.
5. Следующий независимый набор: несколько вкладок, смена мира или новый перенос
   во время подготовки/ожидания первой отправки. Закрепить ожидаемое поведение
   до первого запуска; поздний ответ не должен менять новую игру или чужой
   черновик. Логика guards уже проверена модульно; нужен полный браузерный путь.
6. UX379 и прежние живые хвосты RP370/RP381 закрывать только по факту наблюдения.

## Как повторить проверки

Нужен Node 24 (в этой сессии 24.22.1). На другом ПК найти его установленный путь,
не полагаться на системный Node 20. Все тесты запускаются из корня проекта.

```powershell
npm ci
npm run typecheck
npm run zip
npm run zip:firefox
npx vitest run tests/continuation-flow.test.ts tests/tab-session.test.ts tests/continuation-recovery.test.ts tests/continuation-opening.test.ts tests/service-transport.test.ts tests/continuation-storage.test.ts tests/continuation-long-game.test.ts tests/world-game.test.ts tests/world-game-activation-guard.test.ts --maxWorkers=2
npx playwright test -c playwright.extension.config.ts tests/e2e/continuation-length-runtime.spec.ts --workers 2
npx playwright test -c playwright.extension.config.ts tests/e2e/continuation-chain-runtime.spec.ts tests/e2e/continuation-repeat-runtime.spec.ts tests/e2e/continuation-followup-runtime.spec.ts tests/e2e/automatic-memory-runtime.spec.ts --workers 2
```

Сборку не запускать одновременно с браузерными наборами: нагрузка уже давала
неустойчивые результаты в RP386. На рабочем ПК WXT использовал TEMP/TMP в
`.wxt/build-temp`; это локальная настройка, не требование для домашнего пути.
При regex с `|` не пропускать его через `npx.cmd`: использовать прямой вызов
Node и `node_modules/@playwright/test/cli.js` с корректным quoting.
