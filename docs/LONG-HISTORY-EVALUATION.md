# RP280 — независимая проверка длинной памяти

## Протокол до первого запуска

Проверяется текущий RP279, без изменения алгоритма. Новый набор написан отдельно от прежних RP273/RP277: три истории (заповедник, радиостанция, театр), новые имена, предметы, условия и запросы. Переиспользуются только типы данных и штатная привязка доказательств. Это самостоятельный синтетический набор, созданный тем же агентом, который знает устройство алгоритма; не внешняя слепая оценка и не человеческая разметка.

72 основных сценария: три истории × два языка ×12 запросов. В каждой истории360 последующих сцен, три независимых дела, открытое обещание, завершённая подготовка, отменённая доставка, мнение персонажа, запреты и исправленное постоянное место возврата. Проверяются буквальные вопросы, длинное действие, два/три действия, пересказ без названия предмета, местоимения, скачок времени, конкретный обещавший, неоднозначные подарки, цитата и условное действие. Ещё6 сценариев с250/1000/5000 последующими сценами измеряют масштаб.

До первого вызова компилятора команда `--freeze` сохраняет хеши входов и полный список ожидаемых фактов с исходными цитатами, статусами и источниками. Фиксируются исходники runtime, fixture, runner и этого протокола (нормализация только CRLF→LF). Файл создаётся с `wx`; существующий baseline и отчёты не перезаписываются. В этом этапе нет дообучения/исправления алгоритма по результатам: первый результат становится исходной точкой для будущей работы.

## Метрики и правила

- Полнота: все ожидаемые записи присутствуют целиком. Отдельно публикуется число найденных записей, запросы с потерями и результат по каждой семье/языку. Полный набор включает условия/незавершённость, даже если запрос короткий.
- Доказательства: каждая переданная запись соответствует текущему входному факту; текст, цитата, kind, task, claim, speaker/promisor/believer и revision ID не выдуманы/не изменены. Прежнее место возврата не должно появляться как актуальный факт.
- Местоимения: не считать подбор нескольких кандидатов разрешением личности. Для личных ссылок и неоднозначных подарков требуется штатное предупреждение; качество выбора живой моделью не измеряется.
- Полный бюджет: учитываются вся инструкция и формат columns; превышение допускается только когда обязательная часть сама превышает лимит, и должно быть отражено явно.
- Cold/warm: тот же вход, затем storage clone через scoped индекс; результат и диагностическое состояние должны совпадать. Исходные данные неизменны. Время локального компилятора измеряется отдельно, без загрузки Vite и клонирования; это не время ответа DeepSeek.
- Цитаты и условные действия не размечаются как исполненные события; для них проверяются доказательства и отсутствие изменения входа. Результат поиска сам по себе не исполняет действие.
- Для масштаба публикуются фактические времена каждого из6 сценариев. Один cold и один warm замер на сценарий не дают стабильный benchmark p95 и не доказывают ускорение; результаты зависят от ПК и нагрузки.

Сценарии передают уже принятые факты/порядок источников в компилятор, а не проигрывают360–5000 сообщений через сайт. Здесь не проверяются извлечение фактов моделью, импорт/экспорт, вся UI-матрица, личный лор или реальное окно DeepSeek. Новый формат wire проверяется отдельно от качества поиска.

## Повторение

Полный Git checkout нужен для fixture; source ZIP исключает тесты. Команда запуска: `node scripts/story-search-long-benchmark.mjs --evaluate --report rp280-long-results.json`. Первый запуск до оценки: `--freeze`. Повторная оценка должна использовать новое имя `rp280-*.json` и неизменные замороженные исходники/входы/ожидания. После изменения runtime нужна отдельная явно помеченная seen-регрессия, а для независимой проверки — следующий новый набор.

Результаты этого запуска будут описаны отдельно в `docs/LONG-HISTORY-RESULTS.md`; данный протокол после заморозки не меняется.
