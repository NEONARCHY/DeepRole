## Что теперь известно точно

Отказ происходит в `activateGame("resume")`, до parent/native-history read,
сборки prompt и durable dispatch capture. Зафиксированы миллисекунды,
**таймаут не является причиной этих четырёх диагностических отказов**.
Исходный `story-binding-conflict` возникает либо в background tab guard, либо
в storage при проверке мира/привязки. По одному публичному коду различить нельзя.

Локальные evidence: `.output/rp333-live-diagnostic.json` (последние два отказа
tab680 с полными безопасными console records). Кроп без личной боковой панели:
`benchmarks/rp333-live-activation-failed-20261019.png`.

## Изменения RP333

Сохранён оригинальный публичный `story-binding-conflict`, добавлен **только
статический detail**. Разрешённый список:

- `activation-tab-url`, `activation-tab-chat`, `activation-tab-inactive`;
- `activation-world-missing`, `activation-binding-missing`,
  `activation-binding-world`, `activation-binding-url`.

Те же условия, порядок проверок, исключение mode initialize и pre/post commit
guards. В storage отказ по-прежнему не меняет записи. Error.cause проходит через
существующий repository JSON port только по allowlist; content ещё раз фильтрует
detail. В консоли revision `RP333`. Произвольные причины, URL, chat/world IDs,
ключи, текст лора и native responses не сериализуются.

Новых запросов/повторов модели, новых history GET, доступа к скрытому хранилищу
через автоматизацию, ослабления active-tab или ручного исправления записей нет.
Это уточнение диагностики, **оставшаяся причина пока не исправлена**.

В RU/EN предупреждение больше не утверждает, что память не подготовилась
«вовремя / in time»: общий отказ не доказывает таймаут. Установленная копия
получит текст только после обновления.
