После добавления нового разбора абзаца историческая регистрация RP272 больше не сравнивается с изменяемым `src/core/story-sequence-priority.ts`. Её точный исходник из HEAD сохранён в `docs/benchmarks/rp272-final-sequence.txt`, LF hash `08d93b83fbbc129a89df03ed80c5e2a43296add9a20e48e8f868e1194d9abe3a` совпадает с неизменной регистрацией. Тест нормализует CRLF→LF для воспроизводимости checkout. Прежние current compiler/gold/budget/source checks в этом же файле и новые paragraph tests остаются действующими. Historical report/registration/ожидаемые результаты не переписываются.

## Что исправлено в RP282

Старые тесты RP258–269 вычисляли baseline через текущий компилятор. После появления новых способов подбора это меняло вход старого эксперимента: исходные 5 успешных случаев становились 9, а прежний кандидат с пределом 8 записей получал до 21 записи. Это не основание менять старый результат или ограничивать нынешнюю память.

В `tests/fixtures/historical-search-context.ts` задан явный профиль сравнения RP268. Все параметры перечислены; новый параметр компилятора требует пересмотра профиля через TypeScript. Профиль отключает поздние ветви подбора, но использует текущий код: **это не эмуляция старой версии расширения**. Его пригодность ограничена воспроизведением конкретных сохранённых экспериментов.

Исторические тесты требуют точного совпадения всего измеренного workload, исходных данных, gold, baseline, порядка и provenance с прежними отпечатками. Результаты выбора вычисляются из исходных текстов, ролей и источников, а не берутся из сохранённого отчёта. Подмена gold не должна менять выбор. Старые отчёты, протоколы, алгоритмы кандидатов и ожидаемые 5→16 не изменены.

Один зарегистрированный сырой отпечаток зависит от CRLF. У файла `tests/fixtures/story-search-diverse.ts` восстановлены окончания CRLF, уже закреплённые в `.gitattributes`; его исходный код и регистрация не менялись.

## Проверка сегодняшнего поведения

`tests/story-search-current-contract.test.ts` проверяет 224 исходных сценария с текущими параметрами, включая columns transport: целые существующие факты, точные цитаты, task/claim, отсутствие дублей, общий бюджет, неизменность входа и равенство холодного/прогретого индекса вместе с диагностикой. Проверка полноты lasting recall также выполняется отдельно на текущих параметрах. Прежние индивидуальные проверки источников и ограничений остаются.

Исторический предел 8 принадлежит старому экспериментальному кандидату. Он не применяется к сегодняшнему компилятору. Здесь нет нового результата независимой оценки качества: RP280 остаётся 54/60, а повтор после исправления RP281 — 60/60 на уже известных данных.

## Как воспроизвести

Из Git checkout с установленными зависимостями: `vitest run tests/story-lasting-recall-quality.test.ts tests/story-search-evidence.test.ts tests/story-search-grounding.test.ts tests/story-search-current-contract.test.ts`, затем полный `vitest run` и `tsc --noEmit`. Нужен Node 22, как у рабочего стенда. Тесты и их исходные fixtures исключены из пользовательского source ZIP; для воспроизведения нужен Git checkout.

Старые benchmark CLI по умолчанию используют текущий runtime. Не перезаписывайте ими прежний отчёт и не называйте такой запуск повтором исторического измерения без проверки полного входного отпечатка. Итоговые числа RP282 и границы проверки находятся в начале `CODEX-HANDOFF.md`.
