## Что означает результат

Два независимых итога: `integrityPassed` — проверки сохранности/бюджета/повторов прошли; `recallComplete` — все ожидаемые условия попали в запрос. Первый не подменяет второй. Обычный запуск падает при нарушении проверяемых инвариантов; `npm run test:memory -- --strict-recall` также падает при неполном подборе. Известные дефекты RP292 не помечены ожидаемыми успешными тестами и не удалены: 96 наблюдений обычного режима сохраняют конкретные `missing` и статус покрытия.

Множество пар генерируется детерминированно. Отдельный oracle заново перебирает каждую пару значений, не доверяя заявленному числу генератора. Каждый сгенерированный ряд действительно проходит через production compiler дважды; это не только таблица конфигураций.

## Границы

Это не все возможные комбинации. Попарное покрытие не доказывает все тройки/порядки событий, жизненный цикл не прогоняется декартово со всеми поисковыми настройками. Часть переключателей внутренняя, не пользовательская настройка. 6500 фоновых записей — не 6500 сыгранных сцен. Синтетические уже принятые факты/роли не проверяют извлечение живой моделью. Корпус RP292 уже seen; новый runner не делает его независимой слепой оценкой. Browser/native/live API этим запуском не проверяются. Проверки объяснения warnings/семантического понимания произвольных текстов не обещаются.

Следующее расширение: больше сквозных последовательностей storage → compile с конфликтами, ручной фиксацией канона и несколькими продолжениями; отдельная новая независимая выборка после исправления 21 неполного RP292 запроса. Не менять frozen first report/gold ради зелёного результата.
